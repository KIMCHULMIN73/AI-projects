## 제품 목표

PDF 문서를 끝까지 읽을 시간이 없는 사람이, 파일을 끌어다 놓기만 하면 **한국어로 된 한 줄 요약·요약 문단·핵심 요점**을 받아 문서의 요지를 1분 안팎에 파악하게 한다. 이 기기(Raspberry Pi)에서 로컬로 돌고, 요약은 OpenRouter 무료 모델로만 한다.

**성공 기준** (모두 [SPEC §9](SPEC.md#9-검증-체크리스트와-시험-pdf-만들기)에서 확인)
1. 한국어 텍스트 PDF 1~5쪽을 놓고 [요약하기]를 누르면 30초 안에 한국어 요약이 화면에 보인다. (목표 수치는 제안. [실측 2026-11-17] 짧은 문서 4.4~14.4초, 1순위 실패로 폴백할 때 18~20초 — 통과)
2. 스캔본·암호·손상·PDF 아님·너무 큼·너무 김·무료 한도 소진 등 실패마다, 사용자가 무엇을 해야 하는지 한국어로 안내된다(빈 화면·영문 오류·트레이스백 없음).
3. 요약 1건이 무료 모델 하루 한도(50회)를 6회 넘게 쓰지 않는다. 유료 모델 호출 0회. ([실측] 정상 경로는 문서 길이와 관계없이 1회, 1순위 실패 시 2회 — D15)
4. 업로드한 문서가 디스크·로그에 남지 않고, API 키가 브라우저로 내려가지 않는다.
5. (추가 2026-11-17) 추출을 마친 문서를 [추출한 텍스트 보기]로 새 창에서 쪽·제목·표·그림·목차가 원본과 비슷한 배치로 보고, [추출한 텍스트 다운로드하기]로 글·표·그림이 함께 든 파일 하나를 받아 인터넷 없이 열 수 있다. 이 두 기능은 무료 모델 호출 0회다. ([SPEC §10.11](SPEC.md#1011-검증-체크리스트))

## 단계

처음에는 한 번에 구현하므로 단계를 둘로 나눴고, 2026-11-17 사용자 요청으로 3·4단계(추출한 텍스트 보기·내려받기)를 같은 방식(동시 구현 → 통합 시험)으로 더했다. 뒤 단계를 지워도 앞 단계 결과물은 그대로 실행된다 — 3단계는 새 파일(`pdf_layout.py`·`viewer.*`)과 기존 파일의 덧붙임뿐이고 요약 흐름(`/api/extract`·`/api/summarize`·`llm.py`)을 바꾸지 않는다.

### 1단계 — 동시 구현

- **목표**: backend · ai · frontend가 [SPEC](SPEC.md)의 계약대로 각자 파일을 동시에 만들고, 각자 자기 점검을 통과한다.
- **끝나면 사용자가 할 수 있는 것**: `./run.sh`로 띄워 PDF를 올리고 요약을 받는다(R1~R13).
- **완료 기준**
  - [SPEC §1](SPEC.md#1-파일-구성과-소유권)의 앱 파일이 모두 있고, `./run.sh` 후 `http://127.0.0.1:8030/`에서 `ko.pdf`를 올려 요약 결과가 보인다(실제 호출 1회 이상).
  - [SPEC §9.2](SPEC.md#92-1단계--구현자-자체-점검-모델-호출-0회)의 체크리스트를 세 구현자가 각각 통과하고, 실행한 스크립트와 결과를 보고한다.
  - ai-integration-expert가 고른 무료 모델 두 개(1순위·폴백)와 근거가 보고되어 이 문서 "확정된 결정"에 옮겨진다.
- **하지 않는 것**: 서로의 파일 수정(어긋남은 보고만), 통합 브라우저 시험, 실제 호출 15회 초과(ai).
- **검증 체크리스트**: [SPEC §9.2](SPEC.md#92-1단계--구현자-자체-점검-모델-호출-0회).

### 2단계 — 통합 시험과 최종판

- **목표**: quality-assurance-engineer가 실제 서버·실제 화면으로 여러 상황을 시험하고, 문제가 없어질 때까지 고친다.
- **끝나면 사용자가 할 수 있는 것**: 시험을 마친 최종판을 `./run.sh` → 브라우저(`index.html`)로 쓴다(R14).
- **완료 기준**
  - [SPEC §9.3](SPEC.md#93-2단계--통합-시험-quality-assurance-engineer)의 모든 항목 통과, 실패 0건(남는 것은 사유와 함께 "알려진 문제"로 보고).
  - [SPEC §3](SPEC.md#3-수치-기본값)의 [제안] 수치 중 시간·호출 수를 실측값으로 보고.
  - QA가 고친 앱 코드 목록과 이유가 작업 로그에 남는다.
- **하지 않는 것**: 새 기능 추가(사양 밖이면 제안으로 보고), 배정된 실제 호출 예산 초과(처음 15회, 시험 중 20회로 배정 — 19회 사용, U10).
- **검증 체크리스트**: [SPEC §9.3](SPEC.md#93-2단계--통합-시험-quality-assurance-engineer).

### 3단계 — 추출한 텍스트 보기·내려받기 동시 구현 (추가 2026-11-17)

- **목표**: backend(`pdf_layout.py`·`server.py`·시험 PDF)와 frontend(메인 화면 버튼·보기 창·가짜 서버)가 [SPEC §10](SPEC.md#10-추출한-텍스트-보기내려받기-추가-2026-11-17--34단계)의 계약대로 동시에 만들고 각자 자체 점검을 통과한다. ai-integration-expert는 할 일이 없다(모델 호출 0회, [SPEC §10.12](SPEC.md#1012-ai-integration-expert의-몫)).
- **끝나면 사용자가 할 수 있는 것**: 추출을 마친 문서 카드에서 [추출한 텍스트 보기]를 누르면 새 창에 쪽·제목·표·그림·목차가 보이고, [추출한 텍스트 다운로드하기]를 누르면 `{원본 이름}_추출.html` 파일 하나를 받는다(R15·R16).
- **완료 기준**
  - `./run.sh` 후 `struct.pdf`(제목 h1~h3·3×3 표·그림·책갈피 4개, 2쪽)를 올려 [추출한 텍스트 보기]를 누르면 새 창에 2쪽이 모두 보이고, 목차 4항목, 표 1개(3열×3행, 셀 글자 일치), 그림 1개가 보인다.
  - 같은 문서로 [추출한 텍스트 다운로드하기]를 누르면 `struct_추출.html`이 저장되고, 그 파일을 열면 같은 표·그림·목차가 보이며 파일 안에 `<script`가 없다.
  - 두 기능을 쓰는 동안 실제 모델 호출 0회, 서버 작업 폴더·`/tmp`에 남는 파일 0개.
  - [SPEC §10.11](SPEC.md#1011-검증-체크리스트)의 3단계 체크리스트를 backend·frontend가 각각 통과하고, 기존 자체 점검(`check_server`·`check_llm`·`check_frontend`)도 그대로 통과했다고 실행 결과와 함께 보고한다.
- **하지 않는 것**: 서로의 파일 수정(어긋남은 보고만), 요약 기능·`llm.py` 변경, 통합 브라우저 시험, `.docx` 등 다른 내려받기 형식(U14), 스캔본 글자 인식(D11).
- **검증 체크리스트**: [SPEC §10.11](SPEC.md#1011-검증-체크리스트) "3단계 — backend", "3단계 — frontend".

### 4단계 — 3단계 통합 시험 (추가 2026-11-17)

- **목표**: quality-assurance-engineer가 실제 서버·실제 화면(chromium·Firefox)으로 보기 창과 내려받은 파일을 시험하고, 문제가 없어질 때까지 고친다(D9처럼 모든 파일 수정 가능).
- **끝나면 사용자가 할 수 있는 것**: 시험을 마친 보기·내려받기 기능을 쓴다(R15·R16, R14와 같은 의미의 최종판).
- **완료 기준**
  - [SPEC §10.11](SPEC.md#1011-검증-체크리스트) "4단계" 항목 모두 통과, 실패 0건(남는 것은 사유와 함께 "알려진 문제"로 보고).
  - 내려받은 `.html`이 네트워크 없이 열리고 요청 0회, `xss.pdf`에서 스크립트 실행 0회, 한글 파일 이름 그대로 저장.
  - [SPEC §10.2](SPEC.md#102-수치-기본값-모두-제안--4단계에서-실측-재확인)의 시간 목표(`struct.pdf` 보기 첫 쪽 2초·내려받기 3초, `long.pdf` 첫 5쪽 3초·전체 30초·내려받기 20초)와 300쪽 문서 시간·파일 크기를 실측값으로 보고.
  - 1~2단계 시험 전부 다시 통과. 실제 모델 호출 0회. (구현 후 변경 2026-11-19: 최종 확인용으로 1회 사용 — `:free`, 8.9초)
- **하지 않는 것**: 새 기능 추가(제안으로 보고), `--live` 실행(요약 쪽이 바뀌지 않음).
- **검증 체크리스트**: [SPEC §10.11](SPEC.md#1011-검증-체크리스트) "4단계".

U1~U11은 사용자가 답하지 않아 **기본값대로 구현되어 있다(2026-11-17)**. U14~U20(추가 2026-11-17)은 **기본값대로 3단계에서 구현되었다(2026-11-18, 4단계 시험 통과 2026-11-19 — 사용자 확인 대기)**. U21·U22(추가 2026-11-19)는 4단계 QA의 제안이다. 사용자 확인을 기다린다 — 결정이 바뀌면 이 문서와 SPEC을 고치고, 다시 손볼 코드를 함께 적는다.
