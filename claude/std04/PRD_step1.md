# PRD 1단계 — 냉장고 사진에서 식재료 뽑아내기

> 색인: [PRD.md](PRD.md) · 다음 단계: [PRD_step2.md](PRD_step2.md)

## 목표

사용자가 냉장고 사진을 올리면 **식재료 목록**을 만들어 화면에 보여주고, **사용자가 고칠 수 있게** 한다.

## 완료 기준

1단계는 다음이 되면 끝난 것이다. 2단계를 기다리지 않는다.

- 사진을 올리면 20초 안팎에 재료 목록이 뜬다
- 모델이 잘못 읽은 항목을 **사용자가 고치거나 지우거나 추가**할 수 있다
- 고친 결과가 `IngredientList` JSON으로 남고, 새로고침해도 유지된다
- 이 시점에서 앱은 "냉장고 재료 정리 도구"로서 이미 쓸모가 있다

## 화면 흐름

```
[사진 올리기]  ─사진 선택/드롭/붙여넣기─▶  [미리보기 + 분석 버튼]
                                              │ 20초 (경과 초 표시)
                                              ▼
                                        [재료 목록 — 편집 가능]
                                              │
                                              ▼
                                        (2단계: 레시피 추천 버튼)
```

재료 목록은 **카테고리별로 묶어서** 보여준다. 열 개가 넘어가면 평평한 목록은 읽기 어렵다.

## 데이터 계약 — `IngredientList`

2단계가 받는 것은 이 JSON이다. **2단계는 이것이 사진에서 왔는지 손으로 입력한 것인지 몰라야 한다.**

```json
{
  "items": [
    {
      "name": "달걀",
      "category": "달걀",
      "quantity": "6개",
      "confidence": "high",
      "needs_review": false,
      "source": "vision"
    }
  ],
  "unsure": ["문 안쪽 초록색 병 — 라벨이 가려 무엇인지 모르겠음"],
  "analyzed_at": "2026-09-11T10:00:00+09:00"
}
```

| 필드 | 뜻 |
|---|---|
| `category` | 아래 11개 중 하나. 자유 문자열이 아니다 |
| `confidence` | `high` / `medium` / `low` — 모델의 확신도 |
| `needs_review` | 값이 수상해 사람이 봐야 함 (→ `UNIT_json_contract`의 값 검증) |
| `source` | `vision`(모델이 찾음) / `user`(사람이 추가·수정함) |
| `unsure` | 모델이 있다고는 보는데 무엇인지 모르는 것. **items에 섞지 않는다** |

**카테고리 11개**: `채소` `과일` `육류` `해산물` `유제품` `달걀` `곡물면` `양념소스` `가공식품` `음료` `기타`

이 목록은 스키마의 `enum`이자 화면 그룹의 순서다. 늘리려면 스키마·프롬프트·화면 세 곳을 함께 고친다.

## API

`POST /api/vision` → `{ "image": "data:image/jpeg;base64,..." }` → `{ ok, data: IngredientList, meta }`

프롬프트와 스키마는 **프록시가 가지고 있다.** 브라우저는 사진만 보낸다.

## 프롬프트 (실측으로 다듬은 것)

```
냉장고 사진이다. 보이는 식재료를 빠짐없이 찾아라.
- name_ko: 반드시 한국어 식재료 이름으로 적어라. 포장에 영어가 적혀 있어도
  한국어로 옮겨라 (EGGS→달걀).
- category: 포장의 글자가 아니라 그 식품이 실제로 무엇인지로 분류하라.
  달걀은 '달걀', 우유·치즈·요구르트는 '유제품', 두부는 '가공식품',
  김치는 '가공식품'이다. '양념소스'는 간장·고추장·식용유처럼 조미료일 때만 쓴다.
- quantity: 개수나 용량이 보이면 그대로, 없으면 '미상'.
- 확실하지 않은 것은 items에 넣지 말고 unsure에 이유와 함께 적어라.
```

**카테고리의 뜻을 예시로 박아 넣는 것이 핵심이다.** 이 문장들이 없을 때 분류 정확도가 3/6이었고, 넣은 뒤 5/6이 되었다. 특히 `달걀`을 `양념소스`로 넣는 실수가 사라졌다.

## 사용자가 고칠 수 있어야 하는 이유

장식이 아니라 **필수 기능이다.** 실측에서 모델이 이름을 `달modification달걀`처럼 깨뜨려 내보냈다. 스키마를 강제해도 값의 내용까지는 보장되지 않는다.

- 각 항목은 이름·수량·카테고리를 그 자리에서 고칠 수 있다
- 항목 삭제, 수동 추가 가능
- `needs_review`이거나 `confidence: low`인 항목은 눈에 띄게 표시한다
- `unsure` 목록은 "이런 것도 있는 것 같은데 무엇인가요?"로 보여주고, 사용자가 이름을 붙이면 `items`로 올린다
- 사람이 손댄 항목은 `source: "user"`가 되고 `needs_review`가 풀린다

## 하지 않는 것

- 여러 장 동시 분석 (토큰·대기시간이 장수에 비례한다 → `UNIT_image_input`)
- 유통기한·신선도 판정 (사진으로 알 수 없다. 지어낸 답이 나온다)
- 사진 저장 (개인정보. 분석 후 버린다)
- 재료 사진을 다시 분석해 수량을 갱신하는 기능

## 검증 체크리스트

- [ ] 냉장고 사진을 올리면 재료 목록이 카테고리별로 뜬다
- [ ] 분석 중 경과 초가 올라가고 버튼이 잠긴다
- [ ] 깨진 이름이 `needs_review`로 표시되고, 고치면 표시가 풀린다
- [ ] 항목 추가·수정·삭제가 되고 F5 후에도 유지된다
- [ ] 식재료가 없는 사진(예: 풍경)을 올리면 "찾지 못했습니다"가 뜨고 앱이 죽지 않는다
- [ ] 프록시를 끄고 분석하면 한국어 오류와 재시도 버튼이 뜬다
- [ ] 응답·콘솔·네트워크 탭 어디에도 `sk-or-v1-`이 없다
