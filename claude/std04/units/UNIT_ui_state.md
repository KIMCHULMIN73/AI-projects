# UNIT — 화면 상태와 대기

**쓰는 단계: 1 · 2 · 3**

**1단계 분석이 한 번에 18~23초 걸린다.** 이 앱의 사용성은 대부분 "그 20초를 어떻게 보여주는가"로 결정된다. 아무 표시 없이 버튼만 눌린 채로 두면 사용자는 고장 났다고 판단하고 다시 누른다 — 그러면 무료 모델의 레이트리밋에 걸린다.

## 상태

각 비동기 작업은 네 상태 중 하나다. 화면은 항상 이 중 하나를 분명히 보여준다.

```
idle ──▶ loading ──▶ done
              └────▶ error ──▶ (다시 시도) ──▶ loading
```

| 상태 | 화면 |
|---|---|
| `idle` | 무엇을 하면 되는지 (예: "냉장고 사진을 올려 주세요") |
| `loading` | 진행 표시 + **경과 초** + 예상 시간 |
| `done` | 결과 |
| `error` | 한국어 한 줄 + 재시도 버튼(가능할 때만) |

## 긴 대기 규칙

- **버튼을 즉시 비활성화한다.** 중복 요청이 레이트리밋의 가장 큰 원인이다.
- **경과 시간을 초 단위로 센다.** 멈춘 스피너보다 "12초째 분석 중"이 훨씬 덜 불안하다.
- **예상 시간을 미리 말한다.** "보통 20초쯤 걸립니다"를 먼저 보여주면 20초는 기다릴 만한 시간이 된다.
- 30초를 넘기면 "평소보다 오래 걸리고 있습니다"로 문구를 바꾼다. 60초에 `TIMEOUT`.
- 취소 버튼을 둔다(`AbortController`). 취소는 화면만 되돌린다 — 이미 나간 요청의 토큰은 돌아오지 않는다.

## 오류 표시

- `UNIT_proxy.md`의 `error.message`를 그대로 띄운다. **프록시가 한국어 문구를 만들고 화면은 옮기기만 한다** — 두 곳에서 문구를 만들면 갈라진다.
- `retryable: true`일 때만 재시도 버튼을 보인다. `NO_KEY`에 재시도 버튼을 달면 사용자는 영원히 누른다.
- 예외 원문·스택을 화면에 뿌리지 말 것.

## 접근성·반응형

- 진행 상태는 `aria-live="polite"`로 읽히게 한다. 스피너만 돌면 화면 낭독기 사용자는 아무것도 모른다.
- 480px 이하에서 레이아웃이 깨지지 않아야 한다(형제 프로젝트의 검증 기준).
- `@media (prefers-reduced-motion: reduce)`에서 애니메이션을 멈춘다.

## 검증

- [ ] 분석 중 버튼이 비활성화되고 두 번 눌리지 않는다
- [ ] 경과 초가 올라간다
- [ ] 프록시를 끈 채 시도하면 한국어 오류 한 줄과 재시도 버튼이 뜬다
- [ ] `NO_KEY` 오류에는 재시도 버튼이 없다
- [ ] 480px에서 레이아웃이 유지된다
