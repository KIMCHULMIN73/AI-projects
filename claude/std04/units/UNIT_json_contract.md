# UNIT — 모델에게서 JSON 받아내기

**쓰는 단계: 1 · 2**

**2026-09-14 비전 모델 교체 뒤로 두 모델 모두 스키마 강제를 지원하지 않는다.** 그래서 두 단계 모두 같은 방식(프롬프트로 요구 + 관대한 파싱 + 복구)으로 다룬다.

| | 비전 모델 (1단계) | 텍스트 모델 (2단계) |
|---|---|---|
| `response_format` / `structured_outputs` | **미지원** (ling-3.0-flash-vl) | **미지원** |
| 전략 | 프롬프트로 요구 + 복구 | 프롬프트로 요구 + 복구 |
| 실측 | 실제 사진 4회 연속 펜스 없이 파싱 성공, 카테고리 이탈 0 | 3회 연속 펜스 없이 파싱 성공 |

## 1단계 — 프롬프트로 요구

프롬프트 끝에 형태 예시와 허용 값을 박는다(전문은 `PRD_step1.md`).

```
반드시 아래 JSON만 출력하라. 설명·인사말·마크다운 코드펜스 금지.
category는 채소·과일·…·기타 중 하나, confidence는 high·medium·low 중 하나.
{"items":[{"name_ko":"","category":"","quantity":"","confidence":""}],"unsure":[""]}
```

- **`enum`이 강제되지 않는다.** 모델이 "야채"를 내도 막을 스키마가 없다. 아래 "값 검증"이 유일한 벽이다 — 목록 밖 값은 `기타`로 접고 `needs_review`를 붙인다.
- 형태가 맞아도 **값의 내용까지 보장되지는 않는다.** 옛 모델은 스키마를 지켰는데도 이름을 `달modification달걀`·`달란`처럼 깨뜨렸다.

## 스키마 강제 — 지원하는 모델로 바꿀 때 (지금은 쓰지 않는다)

비전 모델을 다시 `response_format`을 지원하는 모델로 바꾸면 이쪽이 권장 경로다(옛 모델 dots-3-note-preview에서 쓰던 방식).

```json
"response_format": {
  "type": "json_schema",
  "json_schema": { "name": "fridge", "strict": true, "schema": { ... } }
}
```

- `"strict": true`와 `"additionalProperties": false`를 반드시 넣는다. 빼면 모델이 필드를 더 만들어 낸다.
- 카테고리처럼 **값이 정해진 필드는 `enum`으로 못 박는다.** 자유 문자열로 두면 "야채"와 "채소"가 섞여 나와 화면 그룹화가 깨진다.
- 스키마 통과 ≠ 쓸 수 있는 값. 값 검증은 그대로 둔다.

## 2단계 — 프롬프트로 요구

스키마를 못 쓰므로 프롬프트가 계약서다.

```
반드시 아래 JSON만 출력하라. 설명·인사말·마크다운 코드펜스 금지.
{"recipes":[{"title":"","time_minutes":0,"uses":[""],"missing":[""],"steps":[""]}]}
```

빈 값이 든 **형태 예시를 그대로 보여주는 것**이 효과가 가장 좋았다. 필드를 말로 설명하면 이름이 흔들린다.

## 파싱 — 관대하게 받는다

```
1. json.loads(원문)                       ← 실측상 대개 여기서 끝난다
2. 앞뒤 ```json / ``` 펜스를 벗기고 재시도
3. 첫 '{' 부터 마지막 '}' 까지 잘라 재시도   ← 앞에 인사말이 붙은 경우
4. 실패 → 복구 1회
5. 또 실패 → BAD_OUTPUT
```

복구는 **같은 프롬프트를 다시 보내는 것이 아니다.** 모델의 이전 출력을 붙여 "이건 JSON이 아니다. JSON만 다시 출력하라"고 요구한다. 같은 요청을 반복하면 같은 실패가 돌아온다.

## 값 검증 — 스키마를 통과해도 한 번 더 본다

파싱 성공은 시작일 뿐이다. 프록시가 브라우저에 넘기기 전에:

- **이름 문자열**: 아래 중 하나라도 걸리면 `confidence`를 `low`로 낮추고 `needs_review: true`를 붙인다. **버리지 않는다** — 사람이 고칠 수 있게 화면에 올린다.
  - 한글·영문·숫자·공백·괄호 외의 문자가 섞였다
  - 같은 음절이 **연달아** 세 번 이상 나온다 (`토마토`·`바나나`처럼 떨어진 반복은 정상 이름에도 흔하므로 잡지 않는다)
  - **공백 없이 한글과 영문이 붙어 섞였다** (`달modification달걀`). 실측의 깨짐이 바로 이 꼴이었는데, 위 두 규칙으로는 잡히지 않는다 — 전부 허용 문자이고 반복도 떨어져 있다. `KIRKLAND 우유`처럼 공백으로 떨어진 것은 통과시킨다.
- **빈 배열**: `items`가 비면 실패가 아니라 "찾지 못함"이다. 화면이 그렇게 말해야 한다.
- **enum 밖의 값**: `기타`로 접고 `needs_review`를 붙인다.
- **길이 상한**: 이름 40자, 배열 100개. 넘으면 자른다.

`needs_review`가 붙은 항목은 화면에서 눈에 띄게 표시하고, 사용자가 고치기 전까지 다음 단계로 넘기지 않는다.

## 검증

- [ ] 허용 목록(카테고리 11개)에 없는 카테고리가 화면에 나타나지 않는다
- [ ] 모델이 펜스를 붙여도 파싱된다 (응답을 손으로 조작해 재현)
- [ ] 깨진 이름이 버려지지 않고 `needs_review`로 표시된다
- [ ] 파싱 2회 실패 시 `BAD_OUTPUT`이 뜨고 앱이 죽지 않는다
