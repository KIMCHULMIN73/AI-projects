# UNIT — 이미지 입력

**쓰는 단계: 1** · 구현 위치: 브라우저 JS

사용자의 사진을 모델이 먹을 수 있는 형태로 만든다. **축소는 선택이 아니라 필수다.**

## 받는 방법

세 가지 모두 같은 처리로 흘러간다:

- 파일 선택 버튼 (`<input type="file" accept="image/*">`)
- 드래그 앤 드롭
- 붙여넣기 (Ctrl+V) — 스크린샷을 바로 넣을 수 있어 개발 중에 특히 편하다

모바일에서 `accept="image/*"`는 카메라 촬영도 함께 제공한다. 별도 코드가 필요 없다.

## 축소 규칙

| 항목 | 값 | 근거 |
|---|---|---|
| 긴 변 최대 | **768px** | 실제 냉장고 사진 실측(2026-09-14, ling-3.0-flash-vl): 768px **22초**·재료 12개, 512px 24초·10개, 원본 1077px 33초·12개. 512px는 빠르지도 않고 덜 찾는다. 원본 4000px 사진은 base64로 수 MB가 된다 |
| 포맷 | **JPEG** | 냉장고 사진은 사진이다. PNG로 두면 서너 배 커진다 |
| 품질 | **0.85** | 더 낮추면 라벨 글씨가 뭉개져 인식률이 떨어진다 |
| 전송 후 상한 | **4MB** | 넘으면 프록시가 `BAD_REQUEST` |

**768px의 대가(사용자 결정)**: 수량 인식이 회차마다 들쭉날쭉하다. 측정용 호출에서는 거의 '미상'이었고, 프록시를 거친 호출(22초)에서는 달걀 10개·당근 3개처럼 읽었다. 원본 크기에서는 읽었다. 수량이 중요해지면 1024px로 올리고 대기 문구를 "보통 30초"로 바꿀 것(→ `UNIT_ui_state`).

`<canvas>`로 줄이고 `toDataURL('image/jpeg', 0.85)`로 뽑는다. 외부 라이브러리 없이 된다.

- **EXIF 회전을 반드시 처리한다.** 휴대폰 세로 사진은 가로로 눕혀 들어온다. `createImageBitmap(file, {imageOrientation: 'from-image'})`가 가장 간단하다.
- 줄인 결과를 화면에 미리보기로 띄운다. **사용자가 모델에게 실제로 보내지는 그림을 봐야** 인식이 이상할 때 원인을 짐작할 수 있다.

## 전송 형식

```json
{ "image": "data:image/jpeg;base64,..." }
```

프록시는 이것을 그대로 OpenRouter의 `image_url`에 넣는다.

```json
{"type": "image_url", "image_url": {"url": "data:image/jpeg;base64,..."}}
```

## 비용 감각

이미지 한 장은 입력 약 830 토큰이다(768px 실제 사진, 프롬프트 포함). 원본 1077px로 보내면 약 1,190 토큰이다. **여러 장을 한 번에 보내는 기능은 1단계에서 만들지 않는다** — 토큰과 대기 시간이 장수에 비례해 늘고, 무료 모델의 레이트리밋에 바로 걸린다.

## 개인정보

냉장고 사진에는 집 안이 찍힌다. 화면에 한 줄로 알린다: **"사진은 분석을 위해 OpenRouter로 전송되며, 이 앱은 사진을 저장하지 않습니다."** 실제로 저장하지 않는다 — 프록시는 이미지를 디스크에 쓰지 않고, 브라우저도 localStorage에 넣지 않는다(용량상 불가능하기도 하다).

## 검증

- [ ] 4000px 세로 사진을 넣으면 768px로 줄고 똑바로 선다
- [ ] 붙여넣기로 스크린샷이 들어간다
- [ ] 이미지가 아닌 파일(PDF 등)을 넣으면 화면이 거부한다
- [ ] 미리보기에 보이는 그림과 모델이 받는 그림이 같다
