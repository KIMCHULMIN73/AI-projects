# PRD 3단계 — 프로필과 레시피 보관함

> 색인: [PRD.md](PRD.md) · 앞 단계: [PRD_step2.md](PRD_step2.md)

## 목표

여러 사람이 한 브라우저를 나눠 쓸 수 있게 **프로필**을 두고, 2단계가 만든 레시피 중 마음에 드는 것을 **프로필별로 저장**한다.

## 완료 기준

- 프로필을 만들고·이름을 고치고·지우고·전환할 수 있다
- 레시피 카드의 저장 버튼으로 지금 프로필의 보관함에 담긴다
- 보관함에서 다시 꺼내 보고, 지울 수 있다
- F5·브라우저 재시작 후에도 유지된다

## 쓰는 unit

[UNIT_storage](units/UNIT_storage.md) · [UNIT_ui_state](units/UNIT_ui_state.md) · (정적 서빙만) [UNIT_proxy](units/UNIT_proxy.md)

**이 단계는 모델을 부르지 않는다.** API 호출도, 프롬프트도 없다. 순수하게 브라우저 안에서 끝난다.

## 프로필이 하는 일과 하지 않는 일

| 한다 | 하지 않는다 |
|---|---|
| 보관함을 사람별로 나눈다 | **레시피 생성에 영향을 주지 않는다** |
| 화면 상단에 누구인지 표시 | 알레르기·식단 제한 필터링 |
| 프로필별 저장 목록 | 로그인·비밀번호·서버 계정 |

**프로필은 이름표일 뿐이다**(PRD.md 결정표, 사용자 결정). 그래서 2단계는 3단계를 전혀 모르고, 3단계를 나중에 지워도 1·2단계가 그대로 돈다.

이 결정이 막고 있는 것: 우유 알레르기가 있는 사람의 프로필로도 우유가 든 레시피가 추천된다. 그것을 바꾸려면 2단계의 `/api/recipe` 입력에 필드를 더해야 하며, 그때 **2단계와 3단계가 서로 얽힌다.** 얽힐 만한 가치가 있는지는 그때 판단한다.

## 데이터 모양

```json
// fridge.v1.profiles
[{ "id": "p-1", "name": "김철민", "emoji": "🐻", "createdAt": "2026-09-11T10:00:00+09:00" }]

// fridge.v1.activeProfile
"p-1"

// fridge.v1.saved.p-1
[{ "savedAt": "2026-09-11T10:06:00+09:00", "recipe": { ...2단계의 Recipe 객체 그대로... } }]
```

- 레시피는 **2단계 객체를 통째로** 담는다. 필드를 골라 담으면 2단계가 필드를 늘릴 때마다 여기가 깨진다.
- `emoji`는 프로필 구분용이다. 아바타 이미지를 쓰지 않는 이유: 외부 리소스 금지 관례이고, localStorage에 이미지를 넣을 수도 없다.
- 키 규칙·실패 처리·용량은 전부 [UNIT_storage](units/UNIT_storage.md)를 따른다.

## 화면

```
┌─ 상단 ────────────────────────────────┐
│ 🐻 김철민 ▾   [보관함 12]             │  ← 항상 보인다
└───────────────────────────────────────┘
   │ 클릭
   ▼
 프로필 전환 · 새 프로필 · 이름 수정 · 삭제
```

- 프로필 전환은 **페이지를 새로 그리지 않는다.** 보관함 목록만 바뀐다. 분석 중이던 재료 목록은 그대로 둔다 — 재료는 냉장고의 것이지 사람의 것이 아니다.
- 프로필이 하나도 없으면 첫 실행이다. **강제로 만들게 하지 말고** "기본" 프로필을 자동으로 만들어 바로 쓸 수 있게 한다. 이름은 나중에 고칠 수 있다.
- 저장 버튼은 이미 저장된 레시피에서 "저장됨"으로 바뀐다. 같은 `id`를 두 번 담지 않는다.

## 프로필 삭제

- 확인을 한 번 받는다. **그 프로필의 레시피가 몇 개 사라지는지 숫자로 보여준다.**
- `fridge.v1.saved.<id>` 키도 함께 지운다. 남기면 localStorage가 계속 찬다.
- 마지막 하나는 지울 수 없다. 지우면 앱에 프로필이 없는 상태가 되어 예외 처리가 늘어난다.
- 지금 선택된 프로필을 지우면 남은 것 중 첫 번째로 옮긴다.

## 하지 않는 것

- 서버 저장·계정·로그인 (사용자 결정: localStorage만)
- 기기 간 동기화
- 프로필별 비밀번호 — localStorage는 누구나 개발자 도구로 읽는다. **잠긴 것처럼 보이게 만드는 것이 잠기지 않은 것보다 위험하다**

> **나중에 열어 둔 길**: 백업이 필요해지면 보관함을 JSON 파일로 내보내기/가져오기가 가장 작은 해법이다. 서버 저장소를 만들 필요가 없고, `UNIT_storage`의 키 구조를 그대로 파일에 담으면 된다.

## 검증 체크리스트

- [ ] 첫 실행에 "기본" 프로필이 자동으로 생기고 바로 쓸 수 있다
- [ ] 프로필을 2개 만들고 각각 다른 레시피를 저장하면 서로 섞이지 않는다
- [ ] 프로필을 전환해도 화면의 재료 목록은 그대로다
- [ ] 같은 레시피를 두 번 저장할 수 없다
- [ ] 프로필 삭제 시 레시피 개수가 확인창에 나오고, 삭제 후 `saved.*` 키가 사라진다
- [ ] 마지막 프로필은 삭제되지 않는다
- [ ] F5·브라우저 재시작 후에도 프로필과 보관함이 유지된다
- [ ] localStorage를 손으로 깨뜨려도 앱이 죽지 않는다
- [ ] 저장 공간이 찼을 때 조용히 실패하지 않고 사용자에게 알린다
