# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project overview

`std03`은 **"누가누가 잘하나 좌충우돌 퀴즈게임"** — 한 화면에서 진행되는 4지선다 상식 퀴즈 게임이다. 요구사항 전체는 `QUIZ_PRD.md`에 있고, 실제 앱은 `quiz-game/`에 있다.

한국사·과학·세계지리·예술/문화/시사 네 분야에서 각 10문제씩 총 40문제를 풀되 **출제 순서는 분야를 가로질러 섞는다.** 100점에서 시작해 **정답은 난이도만큼(최상+50 / 상+40 / 중+30 / 하+20 / 최하+10), 오답은 난이도와 무관하게 −10**으로 점수가 오르내린다. 끝나면 성적 요약과 누적 랭킹을 보여준다.

문제 은행은 **분야별 100문항, 총 400문항**이다. 한 판에 40문제만 나가므로 재도전할 때마다 문제가 크게 바뀐다.

`QUIZ_PRD.md`가 이 프로젝트의 **사양 원본**이다. 규칙(점수·문항 수·난이도 비율)이나 화면 흐름을 바꿔야 하면 PRD와 이 문서를 함께 고칠 것.

## 실행 방법

**`index.html`을 더블클릭해서 열면 동작하지 않는다.** PRD가 ES Modules를 지정했는데, 브라우저는 `file://`에서 모듈 `import`를 CORS 정책으로 차단하기 때문이다. 이때 `main.js`가 통째로 로드되지 않아 **이벤트가 하나도 바인딩되지 않는다** — 화면은 멀쩡해 보이는데 이름을 넣어도 시작 버튼이 활성화되지 않는 증상으로 나타난다. 그래서 `index.html`에 **module이 아닌 일반 `<script>`로 된 `file://` 감지 안내**를 넣어 뒀다(module 스크립트는 이 상황에서 실행 자체가 안 되므로 반드시 일반 script여야 한다).

```bash
cd quiz-game
./run.sh              # 빈 포트를 찾아 서버를 띄우고 브라우저를 자동으로 연다
./run.sh 8080         # 포트 고정(이미 쓰는 중이면 알려 주고 멈춘다)
NO_OPEN=1 ./run.sh    # 브라우저 자동 실행 없이 서버만
```

- 이 리포지토리 환경에는 **다른 python http.server가 8000번을 이미 쓰고 있을 수 있다.** 그래서 기본 실행은 빈 포트를 자동으로 찾는다. 예전처럼 8000번에 그냥 바인딩하면 파이썬 트레이스백이 그대로 튀어나왔다.
- 외부 노출을 막기 위해 `127.0.0.1`에만 바인딩한다.
- 그래픽 환경(`DISPLAY`/`WAYLAND_DISPLAY`)이 있으면 `xdg-open`으로 브라우저를 자동으로 연다. SSH 등 화면이 없는 환경에서는 자동으로 건너뛴다.

빌드·설치·npm은 없다. 서버는 정적 파일 서빙 용도일 뿐이다.

## 검증 방법

자동화된 테스트 러너는 없다(리포지토리 전체 관례).

### 이 환경의 제약 — 검증 수단이 왜 이렇게 생겼는가

이 라즈베리파이 환경에는 **Node/Deno 같은 JS 런타임도, 조작 가능한 브라우저도, SVG 래스터라이저(rsvg/cairosvg/inkscape)도 없다.** 있는 것은 Python 3.13과 PIL뿐이다. 그래서 검증 도구가 전부 파이썬으로 우회하는 형태를 띤다. 이 제약을 모르면 아래 도구들이 왜 이렇게 만들어졌는지 이해되지 않는다.

### 1. 문제 은행 검증

```bash
cd quiz-game
python3 tools/validate_bank.py
```

`questions.js`를 파싱해 스키마를 검사하고, `storage.js`의 샘플링 알고리즘을 **파이썬으로 이식해** 분포를 500회 시뮬레이션한다. **`storage.js`의 샘플링 로직을 고치면 이 스크립트의 이식본도 같이 고쳐야 한다** — 자동으로 동기화되지 않는다.

### 2. 뷰 단독 확인

`./run.sh` 후 `preview.html`. 더미 데이터로 4개 화면과 정답/오답 팝업, 빈 랭킹, 배경 순환을 버튼 하나로 띄워 본다. 게임 로직 없이 모듈2만 본다.

### 3. 제목 SVG 글자 모양 확인

SVG 래스터라이저가 없어 브라우저 없이는 글자 모양을 볼 수 없다. 필요하면 **생성기의 도형 데이터를 PIL로 직접 그려** 확인한다 — `title-svg-generator.py`를 import 해서 `build()`가 돌려주는 획/구멍 좌표를 같은 규칙(둥근 캡·조인, 구멍은 배경색으로 덮기)으로 렌더하면 된다. 실제로 이 방법으로 `충`의 받침 `ㅇ`이 납작하게 뭉개진 것을 찾아 고쳤다. 새 음절을 추가했을 때 유용하다.

### 4. 브라우저 수동 확인

나머지는 전부 수동이다. 시나리오는 맨 아래 통합 검증 체크리스트를 따른다.

`preview.html`과 `tools/*`는 **앱이 로드하지 않는다** — 셋 다 지워도 게임은 그대로 동작한다.

**의존 방향은 단방향이다: 모듈3 → 모듈1, 모듈3 → 모듈2.** 모듈1과 모듈2는 서로를 모르고, 둘 다 모듈3을 모른다.

- **모듈1이 노출**: `getQuizSet()`, `Storage.saveRecord()`, `Storage.getRankings()`, `CATEGORIES`
- **모듈2가 노출**: `Views.showStart()`, `Views.showQuestion(q, state)`, `Views.showFeedback(...)`, `Views.showResult(summary)`, `Views.showRanking(list)`, `Views.setBackground(category)`
- **모듈3**: 위 둘을 import 해 흐름을 구동

`views.js`는 **그리기만** 한다 — 이벤트를 직접 바인딩하지 않고 버튼에 `data-index`만 부여하며, 실제 바인딩은 `main.js`가 한다. 뷰에 로직이 새어 들어가면 이 분리가 무너진다.

## 확정된 설계 판단 (PRD에 없거나 PRD와 충돌한 지점)

1. **ES Modules 유지 + 로컬 서버.** PRD §0은 "ES Modules"와 "`index.html` 열면 바로 동작"을 동시에 요구하지만 둘은 양립하지 않는다. 모듈 분리가 PRD의 핵심 유지보수 전략이므로 ES Modules를 택하고 `run.sh`를 추가했다. (사용자 확인 완료)
2. **에셋 자동 폴백.** PRD §8은 `assets/`에 배경·BGM·효과음이 미리 배치돼 있다고 전제하지만 실제 파일은 없다. 파일이 있으면 쓰고, 없으면 **분야별 CSS 그라디언트 배경 + Web Audio 합성음**으로 대체한다. 나중에 `assets/`에 파일만 넣으면 코드 수정 없이 그대로 쓰인다. (사용자 확인 완료)
3. **문제 은행 400문항 + 난이도 5단계.** PRD는 "분야별 최소 15문항(총 60)"과 난이도 4단계를 요구했으나, 한 판이 40문제라 그 정도로는 재도전 시 문제가 거의 겹친다. 사용자 요청에 따라 **분야별 100문항(총 400)**으로 늘리고 난이도도 **최상/상/중/하/최하 5단계(10:20:40:20:10)**로 바꿨다. (사용자 지시)
4. **제목 글씨체는 VT323이 아니라 SVG 금속 조각.** PRD §0은 "못박힌(도트매트릭스) 글씨체 = VT323"이라고 적었지만, 이는 원본 요청(`QUIZ_PROMPT.CLAUDE`)의 "할일 리스트에서 썼던 못박힌 글씨체"를 잘못 옮긴 것이다. `std02/new version`의 실제 제목은 VT323이 아니라 **나무 널판지 + 못 4개 + 획마다 리벳 구멍이 뚫린 SVG 글자**다. 사용자 확인을 거쳐 std02 방식으로 되돌렸다. VT323은 제목이 아닌 **점수·수치 표시용**으로만 남아 있다.

# 구현 로그

PRD §10의 빌드 순서(모듈1 → 모듈2 → 모듈3)대로 진행한다.

## ✅ 모듈 1 — 데이터 계층 (완료)

UI·사운드 코드 없음. 순수 데이터/로직만.

### `data/questions.js` + `data/questions/`

문항이 400개로 늘면서 한 파일이 3,000줄을 넘게 되어 **분야별 파일 4개로 쪼갰다.** `data/questions.js`는 그것을 합쳐 내보내는 진입점일 뿐이라 **모듈1의 공개 인터페이스는 그대로**이고, `storage.js`·`views.js`·`game.js`는 파일이 나뉜 사실을 모른다.

- `QUESTION_BANK` — **400문항**. 분야별 100문항, 각 분야 난이도 구성은 `top:10 / high:20 / mid:40 / low:20 / bottom:10`.
  - 샘플링 할당량(`top1/high2/mid4/low2/bottom1`)의 10배라 재도전할 때마다 문제가 크게 바뀐다.
- 분야 파일은 `category`를 파일 상단 상수 `C`로 묶는다 — 100번 반복하지 않으려고. 문항을 다른 분야 파일로 옮기면 `category`도 자동으로 따라 바뀐다.
- 파일 안에서는 **쉬운 것부터 어려운 순**(bottom → top)으로 모아 두고 구간마다 주석을 달았다. 난이도별 개수를 눈으로 셀 수 있게 하기 위해서다.
- `CATEGORIES` — 분야별 `{label, icon}`. **화면 라벨의 유일한 출처**이므로 뷰에서 문자열을 하드코딩하지 말 것.
- `CATEGORY_ORDER` — 출제·표시 순서(한국사→과학→세계지리→예술). `Object.keys` 순서에 의존하지 않으려고 따로 뒀다.
- `DIFFICULTY_ORDER` — `['bottom','low','mid','high','top']`. **정렬 순서 자체가 의미를 갖는다** — 인접 난이도 보충 로직이 이 배열의 인덱스 차이를 난이도 거리로 쓴다. 순서를 바꾸면 보충 로직이 깨진다.
- 진입점 파일 맨 위에 "새 문항 추가 방법" 주석.

**난이도 5단계의 뜻**(문항을 새로 쓸 때 이 기준으로 배정한다):

| 코드 | 표기 | 기준 | 분야당 |
|---|---|---|---|
| `bottom` | 최하 | 대부분 맞춘다 | 10 |
| `low` | 하 | 알 만한데 실수로 틀릴 수 있다 | 20 |
| `mid` | 중 | 정답률 절반쯤 | 40 |
| `high` | 상 | 이 정도 알면 유식하다는 소리를 듣는다 | 20 |
| `top` | 최상 | 상식이라기엔 다소 어렵다 | 10 |

### `js/storage.js`

- `getQuizSet({ exclude })` — 분야별 10문제씩 40문제 반환.
  - 난이도 할당량 `{top:1, high:2, mid:4, low:2, bottom:1}`로 샘플링 — 요청 비율 10:20:40:20:10과 같다. **합이 `QUESTIONS_PER_CATEGORY`(10)와 일치해야 한다.**
  - **부족 시 인접 난이도로 보충**: `nearestAvailable()`이 `DIFFICULTY_ORDER` 인덱스 거리로 가장 가까운 난이도를 고른다. 지금 은행은 여유가 있어 이 경로를 타지 않지만, 문항이 적은 분야를 추가하면 동작한다.
  - **마지막에 40문제 전체를 다시 섞는다** — 분야별로 뽑되 출제 순서는 분야를 가로지른다. 분야별 문항 수(10개씩)는 그대로고 섞이는 것은 순서뿐이다.
  - **`exclude`(직전 판 문항 id)는 제외가 아니라 후순위**다. 난이도별로 "안 나온 것 먼저 → 나온 것" 순으로 이어 붙여 두고 앞에서부터 잘라 쓰므로, 어떤 난이도가 바닥나도 **할당량과 비율은 항상 지켜진다.** 중복 회피는 최선 노력일 뿐이다. 지금은 은행이 할당량의 10배라 실제로는 겹침이 0이다.
- `Storage.saveLastQuestionIds(ids)` / `getLastQuestionIds()` — 직전 판 문항 id. 키는 `quiz.lastSet`.
  - **저장 실패를 경고조차 하지 않고 삼킨다.** 실패해도 다음 판에 문제가 좀 겹칠 뿐이라 사용자에게 알릴 가치가 없다(랭킹 저장 실패와 성격이 다르다).
  - localStorage에 두므로 새로고침 후 이어서 해도 직전 판을 피한다.
- `Storage.saveRecord(record)` / `Storage.getRankings()` / `Storage.clearRankings()`
  - 키는 `quiz.rankings`.
  - 정렬: **점수 내림차순, 동점이면 최신순**(`playedAt` 내림차순).
  - `localStorage` 접근은 전부 try/catch. **저장 실패 시 예외를 밖으로 던지지 않고 `false`를 반환**한다 — 저장 실패로 게임이 멈추면 안 되므로. 읽기 실패나 깨진 JSON은 빈 배열로 복구.
- 파일 하단에 콘솔 테스트 예시 주석.

## ✅ 모듈 3 — 게임 로직 & 사운드 (완료)

### `js/audio.js`

- **에셋 유무를 조사해 파일 재생과 합성음 중 하나를 고른다.**
  - BGM: 네 파일에 `HEAD` 요청 → **하나라도 있으면 파일 모드**, 전부 없으면 합성 모드. (일부만 넣으면 없는 트랙 차례에 소리가 끊기므로 넣으려면 4개 다 넣을 것)
  - 효과음: `correct`/`wrong`을 각각 독립 판별. 조사 전 첫 호출은 합성음으로 즉시 반응하고 결과는 다음 호출부터 반영한다(첫 정답에서 소리가 늦지 않도록).
- 합성 BGM은 **장5음계 아르페지오 + 베이스**를 Web Audio로 스케줄링한다. 트랙마다 조성·패턴·템포가 달라 `nextBgm()` 하면 분위기가 바뀐다. `LOOKAHEAD_MS`/`SCHEDULE_AHEAD`로 미리 예약해 끊김을 막는다.
- `startBgm()`은 **시작 버튼 클릭 시점**에만 불린다(자동재생 정책). `AudioContext`가 suspended면 `resume()`.
- 자동재생이 막히면 `play()` 실패를 조용히 삼킨다 — 소리 때문에 게임이 멈추면 안 된다.
- 계약 외 추가: `setMuted()`/`isMuted()` (main.js에서 **M 키**에 연결).
- 전역 `Audio` 생성자와 이름이 겹치므로 오디오 요소는 `document.createElement('audio')`로 만든다.

### `js/game.js` — 상태머신

`START → PLAYING → FEEDBACK → … → RESULT → RANKING`. `state.phase`로 전이를 막아 **중복 클릭·잘못된 시점의 입력을 무시**한다(`answer()`는 PLAYING에서만, `next()`는 FEEDBACK에서만, `retry()`/`finish()`는 RESULT에서만).

- 점수: 100에서 시작. **정답은 난이도별 배점(`POINTS_BY_DIFFICULTY` — 최상50/상40/중30/하20/최하10), 오답은 언제나 −10.** 표에 없는 난이도가 들어와도 멈추지 않도록 `FALLBACK_POINTS`(10)를 둔다.
  - **점수 규칙은 모듈3의 소관이므로 뷰는 배점표를 모른다.** 화면에 띄울 값은 `showQuestion(q, { …, points })`로 넘겨 준다. 뷰가 난이도별 점수를 직접 계산하면 규칙이 두 군데로 흩어진다.
- **배경과 BGM을 떼어 놨다.** 출제 순서를 섞은 뒤로는 분야가 거의 매 문제 바뀌기 때문이다.
  - 배경: 문제의 분야를 따라간다. `setBackground`가 같은 키면 스스로 no-op이라 연달아 같은 분야가 나와도 헛일하지 않는다.
  - BGM: 분야가 아니라 **진행 문항 수**를 따라 `BGM_SWITCH_EVERY`(10)마다 바꾼다 — 한 판에 4곡으로 예전과 같다. 분야마다 갈아 끼우면 파일 모드에서 곡이 매번 처음부터 다시 시작해 음악이 성립하지 않는다. (섞기 전에는 `lastCategory`로 판별했으나, 섞은 뒤로는 그 방식이 성립하지 않아 바꿨다.)
- `tally[category] = {correct, total}`로 분야별 정답을 누적하고, `buildSummary()`가 이걸로 정답률과 `byCategory`를 만든다.
- `retry()` — 문제를 새로 샘플링하고 100점 리셋, 이름은 유지.
- `finish()` — `saveRecord()` → `getRankings()` → `showRanking()`, `stopBgm()`. **저장이 실패해도(사생활 보호 모드 등) 이번 판 기록을 목록에 끼워 넣어 보여 준다** — 저장 실패로 성적을 못 보는 일이 없게.
- `highlightIndex`는 `playedAt + name`으로 찾는다(동점·동명이인 구분).

### `js/main.js` — 부팅 & 배선

- 보기 버튼은 **이벤트 위임**(`#choices`에 한 번만 바인딩) — `showQuestion`이 버튼을 매번 새로 그리기 때문에 개별 바인딩은 유지되지 않는다.
- 이름이 비면 시작 버튼 비활성화 + 안내 문구(F-1).
- 키보드: **1~4** 보기 선택, 팝업에서 **Enter/Space** 다음 문제, **M** 음소거. 이름 입력 중에는 단축키가 글자를 가로채지 않도록 `HTMLInputElement` 가드.
- `type="module"`은 defer지만 방어적으로 `readyState`를 확인해 부팅한다.

- [ ] "다시 도전" 시 문제가 새로 샘플링되고 100점부터 다시 시작한다
- [ ] "종료" 시 랭킹에 이름·점수가 순위대로 추가되고, 내 기록이 강조된다

## 사후 수정 이력 (실행해 보고 발견한 것들)

구현을 마친 뒤 사용자가 실제로 돌려 보며 나온 문제와 그 조치다. 같은 곳을 다시 건드릴 때 참고할 것.

### 1. `run.sh`가 파이썬 트레이스백을 뱉으며 죽음

**원인:** 8000번 포트를 **다른 python http.server가 이미 점유** 중이었다(이 리포지토리 환경에 상시 떠 있을 수 있다). `python3 -m http.server 8000`을 그대로 `exec` 하니 `OSError: [Errno 98] Address already in use`가 날것으로 노출됐다.

**조치:** 기본 실행은 8000~8020에서 빈 포트를 찾아 쓰고, 옮겼으면 그 사실을 알린다. 포트를 명시했는데 사용 중이면 **마음대로 옮기지 않고** 원인·해결책을 안내하고 종료한다. 겸사겸사 `--bind 127.0.0.1`로 외부 노출도 막았다.

### 2. `index.html`을 직접 열면 이름을 넣어도 시작 버튼이 안 켜짐

**원인:** 고장이 아니라 `file://` + ES Modules의 구조적 제약이다. `main.js`가 CORS로 차단돼 **이벤트가 하나도 바인딩되지 않으므로** 입력 핸들러도 안 붙어 버튼이 계속 비활성으로 남는다. **문제는 화면이 멀쩡해 보여 원인을 알 수 없다는 점**이었다.

**조치:** `index.html`에 일반 `<script>`로 `location.protocol === 'file:'`을 감지해 "로컬 서버로 열어 주세요" 안내를 띄운다. 근본 해결(=번들링해서 file://에서 돌리기)은 모듈 분리를 포기해야 하므로 택하지 않았다.

### 3. `run.sh`를 실행해도 브라우저가 안 뜸

**원인:** 원래 서버만 띄우는 스크립트였고 브라우저를 열지 않았다. 주소를 직접 입력해야 했다.

**조치:** `xdg-open`으로 자동 실행. 서버가 뜬 뒤 열리도록 1초 대기 후 백그라운드 실행하고, 그래픽 환경이 없으면 건너뛴다. `NO_OPEN=1`로 끌 수 있다.

### 4. 제목의 `충`에서 받침 `ㅇ`이 납작하게 뭉개짐

**원인:** D 규칙(초성+가로모음+받침)의 받침 박스 폭이 84라 `ㅇ`을 넣으면 가로로 늘어난다. std02에는 `ㅇ` 받침이 없어 드러나지 않던 문제였다.

**조치:** `충`만 D 규칙을 쓰지 않고 받침 박스를 폭 44로 좁혔다. PIL 렌더로 확인 후 수정.

### 5. 문항 교차 검증 — 정답이 둘이 되는 문항 2건

아래 「퀴즈 문제 교차 검증 가이드라인」이 추가된 뒤 기존 72문항을 그 기준으로 전수 점검했다. **`validate_bank.py`는 스키마와 분포만 보고 문항 내용은 보지 않으므로 이 점검은 자동화되지 않는다** — 문항을 추가할 때마다 사람이 해야 한다.

**정답이 둘이 되던 것(수정):**

- `SC-012` — "가장 넓은 **면적**을 차지하는 기관"의 답을 피부로 뒀는데, 면적 기준이면 융모까지 포함한 **소장**(약 30㎡)이 피부(약 2㎡)보다 훨씬 넓다. 하필 소장이 보기에 있었다. 해설도 "가장 크고 무거운"이라며 질문과 다른 기준을 말하고 있었다. → 질문을 **"가장 무거운 기관"**으로 바꾸고 보기의 소장을 뇌로 교체.
- `KH-009` — "임시정부가 **처음** 수립된 도시"의 답을 상하이로 뒀는데, 1919년에 임시정부는 세 곳에서 따로 섰다(연해주 3/17 → 상하이 4/11 → 한성 4/23). 시기 기준이면 블라디보스토크가 먼저이고, 그 블라디보스토크가 보기에 있어 **아는 사람일수록 틀리는** 구조였다. → 질문에 "3·1 운동 직후 **중국에서** 수립된"을 넣어 범위를 한정하고 보기에서 블라디보스토크를 뺐다.

**기준이 모호하던 것(보완):** `KH-004`("삼국 가운데"라며 보기에 가야를 넣어 실질 3지선다 + 공인/전래 용어 혼용), `WG-003`(에베레스트 높이를 2020년 공동 발표치 8,848.86m로 갱신하고 질문에 "해발고도" 명시), `WG-013`(안데스 "세계에서 가장 긴" → "육지에서 가장 긴"), `WG-017`(사해 수심은 해마다 낮아지는 변동값이라 시점 명기).

### 6. 난이도 라벨 재배치

정확성과 별개로 라벨이 체감과 어긋났다. `high`인데 쉬운 것(SC-014 원자번호 1번, SC-013 상대성이론, AC-015 돈키호테), `mid`인데 매우 쉬운 것(KH-006 고려 건국)이 섞여 한 판의 체감 난도가 평평했다.

**분야별 개수(`top:2 / high:4 / mid:9 / low:3`)를 그대로 둔 채 라벨만 맞바꿨다** — 개수를 건드리면 샘플링 여유분이 줄어 재도전 시 문제가 덜 바뀐다. 16개 문항의 라벨이 이동했고 `validate_bank.py` 18/18 PASS를 유지한다.

### 7. 문항 400개로 확장 (분야별 100)

72문항으로는 한 판 40문제를 감당하기에 부족하다는 지적에 따라 **분야별 100문항, 총 400문항**으로 늘리고 난이도를 **4단계 → 5단계**(최상/상/중/하/최하 = 10:20:40:20:10)로 바꿨다.

- **`bottom`을 새로 추가**했다. 기존 `low/mid/high/top` 이름은 그대로 둬서 이미 붙어 있던 라벨이 통째로 뒤집히지 않게 했다.
- **파일을 분야별로 쪼갰다**(`data/questions/*.js`). 3,000줄짜리 단일 파일은 사람이 검토할 수 없다. `data/questions.js`가 합쳐 내보내므로 **모듈1의 공개 인터페이스와 나머지 모듈은 무변경**이다.
- `validate_bank.py`도 4개 파일을 읽도록 고쳤다. `category: C` 상수를 쓰므로 **파일명에서 분야를 알아낸다**(`CATEGORY_FILES`).

**작성 직후 발견한 결함 — 정답 위치가 0번에 79% 쏠림.** 400문항 중 317개의 정답이 첫 보기였다. **첫 보기만 찍어도 79점**이 나와 게임이 성립하지 않는 상태였다. 스크립트로 보기 순서를 섞어 0~3에 균등 배분(98/104/107/91)했다.

그 과정에서 연도·개수 같은 **숫자 보기까지 뒤섞여**(`1945년, 1910년, 1929년, 1919년`) 눈에 거슬리게 되었다. 네 보기가 모두 숫자를 담은 29문항은 **오름차순으로 되돌리고** `answerIndex`를 다시 계산했다.

> 문항을 대량으로 추가하면 정답 위치가 한쪽으로 쏠리기 쉽다. 추가 후 `answerIndex` 분포를 꼭 세어 볼 것 — `validate_bank.py`는 이걸 검사하지 않는다.

### 8. 출제 순서 셔플 · 직전 판 회피 · 난이도별 배점

사용자 추가 요청 3건을 반영했다.

**(1) 출제 순서를 분야 가로질러 섞기** — `getQuizSet()`이 마지막에 40문제 전체를 셔플한다. 분야별 문항 수는 그대로다.

> 이 변경이 **BGM 전환 방식을 깨뜨렸다.** 기존 `game.js`는 `lastCategory`가 바뀔 때 `nextBgm()`을 불렀는데, 순서를 섞으면 분야가 거의 매 문제 바뀌어 곡이 계속 처음부터 다시 시작된다. 그래서 **배경은 분야를 따라가고 BGM은 문항 수(10문제마다)를 따라가도록 분리**했다. 한 판에 4곡이 흐르는 것은 예전과 같다.

**(2) 직전 판 문항 회피** — `getQuizSet({ exclude })`. **제외가 아니라 후순위**로 다뤄서 난이도 비율이 절대 무너지지 않게 했다(위 storage.js 항목 참고). 직전 판 id는 `quiz.lastSet`에 저장해 새로고침 후에도 이어진다. 검증: 연속 2판 200회에서 겹침 최대 0개, 비율 유지.

**(3) 난이도별 배점** — 정답 최상50/상40/중30/하20/최하10, 오답은 일괄 −10. 문제 앞에 배점 뱃지(`.question-points`)를 크게 띄우고 **난이도에 따라 색을 달리했다**(회색→초록→파랑→주황→빨강). 숫자는 VT323으로 크게 뽑는다. 720px 이하에서는 뱃지를 문제 위로 올린다(옆에 두면 문제 글이 눌린다).

`validate_bank.py`도 함께 고쳤다 — **"분야 블록 순서 유지" 검사는 이제 성립하지 않으므로** "분야별 10문제씩 + 순서가 섞였는지"로 바꾸고, 직전 판 회피 검사 2건을 새로 넣었다(21개 검사).

### 10. 한국사 100문항 재점검 — 보기에 숨어 있던 결함

§9는 400문항을 한 번에 보느라 판정이 문제 텍스트에 치우쳤다. 분야 하나만 100문항씩 보기 4개까지 정독하니 **텍스트만 봐서는 오탐으로 보이던 것에서 진짜 결함이 나왔다.**

### 11. `/quiz-add` — 문항 추가를 명령어로

문항을 추가할 때마다 같은 일을 반복하게 돼서 `.claude/commands/quiz-add.md`로 묶었다. `/quiz-add <분야> <난이도> <개수>`.

손으로 하면 반드시 틀리는 부분이 **id 재부여**다. 분야 파일은 쉬운 것부터 어려운 순으로 문항을 모아 두고 id를 파일 순서대로 매기므로, 중간 난이도 구간에 문항을 넣으면 **뒤쪽 id가 통째로 밀린다**(과학 `하`에 2개를 넣으면 SC-031~SC-100이 SC-033~SC-102가 된다). 그래서 `tools/insert_questions.py`를 따로 뒀다 — 삽입·재부여·머리말 개수 갱신을 한 번에 하고, **밀린 id가 어느 문서에 적혀 있는지까지 짚어 준다**(CLAUDE.md의 사후 수정 이력이 id로 문항을 가리키기 때문이다).

**`validate_bank.py`의 기대 구성표를 분야별로 쪼갰다.** 예전 `EXPECTED_BANK_MIX`는 네 분야에 공통으로 적용되는 `{top:10, high:20, mid:40, low:20, bottom:10}` 하나였다. 한 분야의 한 난이도만 늘리면 이 검사가 **반드시 FAIL**로 떨어지는데, 정작 게임은 멀쩡하다 — 샘플링이 요구하는 것은 분야당 `top1/high2/mid4/low2/bottom1`뿐이고 문항이 늘어난 것은 여유가 커진 것일 뿐이기 때문이다. 검사가 늘 빨간 상태면 아무도 안 보게 되므로, 표를 분야별로 만들고 삽입 스크립트가 해당 행을 자동으로 올리도록 했다. 검사의 뜻은 "구성이 **의도치 않게** 흘러내렸는지"로 바뀌었다.

명령어 문서에는 이 프로젝트가 실제로 데인 자리(범위 밖 보기 · 같은 것을 가리키는 보기 둘 · 잣대가 갈리는 최상급 · 다른 잣대의 정답이 보기에 섞임)와 정답 위치 쏠림·숫자 보기 오름차순 규칙을 함께 적어 뒀다. 스크립트의 중복 검사는 **질문 문자열만** 보므로, 표현이 다른 같은 문항을 거르는 일은 여전히 사람 몫이다.

### 12. `/quiz-add` 첫 사용 — 과학 `상` 10문항 (총 410)

`/quiz-add 과학 상 10`으로 과학 상 난이도를 20 → 30문항으로 늘렸다. **은행이 400 → 410문항**이 되어 분야별 개수가 처음으로 달라졌다(과학만 110).

새 문항 SC-091~SC-100은 물리·화학·생물·지구/천문에 고루 걸쳤다 — 전반사(광섬유), 물의 비열, 동소체, 동위원소, 우라늄-235, 효소의 열 변성, 삼투, 소뇌, 맨틀, 광년. 기존 `상` 20문항이 **"…를 발견한 과학자는?" 형태에 몰려 있어**(톰슨·러더퍼드·퀴리·뢴트겐·패러데이) 인물 문제를 하나도 넣지 않고 현상·개념 쪽으로 채웠다.

가이드라인을 적용한 자리:

- `SC-099` 맨틀 — `가장 큰`에 **부피 기준**을 박고, 해설에 "질량으로 따져도 맨틀"을 덧붙여 잣대가 갈릴 여지를 없앴다(약 84%)
- `SC-095` 우라늄-235 — `상업` 원자로로 범위를 한정했다. 우라늄-233도 핵분열성이지만 상업 발전에는 쓰이지 않아, 한정이 없으면 아는 사람이 흔들린다
- `SC-100` 광년 — 네 보기가 모두 수치라 **오름차순을 유지**했다
- `SC-093`(동소체)과 `SC-094`(동위원소)는 서로를 오답 보기로 쓰지 않았다. 한 판에 둘 다 나오면 앞 문항의 해설이 뒤 문항의 답을 알려 주기 때문이다

**밀린 id: SC-091~SC-100 → SC-101~SC-110**(최상 구간 전체). 스크립트가 짚어 준 문서 참조 5건은 **전부 오탐**이었다 — `SC-001 ~ SC-100`은 범위 표기이고 나머지는 명령어 문서의 예시다.

검증: `validate_bank.py` 21/21 PASS. 새 구간 정답 위치 0·1·2·3에 3/2/3/2로 흩고 연속 중복 없음. 은행 전체는 101/107/110/92(최대 26.8%).

> **인수 치환 버그를 이때 발견해 고쳤다.** 이 하네스는 슬래시 명령어의 위치 인수가 **0-based**라 `$1`이 두 번째 인수로 들어온다(`/quiz-add 과학 상 10` → `$1`=상, `$2`=10, `$3`=미치환). `quiz-add.md`와 `quiz-range.md` 모두 `$ARGUMENTS` 한 덩어리만 받아 스크립트 안에서 골라내도록 바꿨다. **새 명령어를 만들 때 위치 인수를 쓰지 말 것.**

### 13. `/quiz-stats` — 편향을 눈이 아니라 χ²로 판정

`/quiz-stats [분야]`. 분야를 비우면 은행 전체, 주면 그 분야만 본다(여러 개 나열 가능). 개수·난이도 분포·정답 위치 편향 셋을 낸다. **문항 내용은 전혀 보지 않는다** — 그건 `/quiz-validate`의 몫이다.

세 명령어의 역할을 갈라 뒀다: `/quiz-stats`는 **분야/은행 전체의 분포**, `/quiz-range`는 **번호 구간**, `/quiz-validate`는 **문항 내용**.

**편향 판정에 χ² 검정(자유도 3)을 썼다.** 눈으로 "0번이 좀 많네"를 판정하면 표본 크기를 무시하게 되기 때문이다 — 10문항 중 4개가 0번인 것과 400문항 중 160개가 0번인 것은 비율이 똑같이 40%지만 전혀 다른 이야기다. 임계값은 7.81(p<0.05, ⚠️)과 11.34(p<0.01, 🔴)이고 20문항 미만은 판정을 보류한다.

그물이 실제로 작동하는지 합성 데이터로 시험했다. §7에서 겪은 **400문항 중 317개가 0번**인 사고는 χ²=628로 🔴, 한쪽에 40%(400문항)는 χ²=48로 🔴. 반면 100문항에서 한쪽이 31%(χ²=2.48)나 20문항에서 40%(χ²=2.40)는 통과시킨다 — 그 크기에서는 우연으로 설명되는 범위라 맞는 판정이다.

비율과 별개로 **같은 정답 위치가 연달아 이어진 최장 구간**도 낸다. 비율이 완벽해도 한자리에 몰려 있으면 플레이 중에 눈치채기 때문이다. 현재 은행은 최장 4연속(과학 SC-066~069)으로 손볼 수준이 아니다.

현재 은행 전체는 101/107/110/92, χ²=1.84로 고르다.

### 14. `/quiz-daily` — 7단계 루틴, 그리고 id 재부여의 진짜 비용

`/quiz-daily [개수] [분야]`. 은행을 진단해 **가장 부족한 자리에 스스로 채운다**(`/quiz-add`는 어디에 넣을지 사람이 정해서 부른다). 7단계를 순서대로 밟고 **단계마다 검증하며, 실패하면 즉시 중단**한다.

**되돌림 지점을 1단계에 둔 이유.** 사용자가 정한 순서에서 백업은 6단계(문항 추가 뒤)다. 그런데 5단계 검증이 깨졌을 때 6단계 백업은 **이미 망가진 은행**을 담게 되어 구제책이 못 된다. "실패하면 즉시 중단"이 성립하려면 되돌릴 수 있어야 하므로, **1단계에서 되돌림 스냅숏을 먼저 잡는다.** 둘은 목적이 다르다 — 1단계는 되돌리기 위한 것, 6단계는 검증을 통과한 상태를 보관하기 위한 것이다.

**새 도구 둘.**

- `tools/bank_report.py` — 현황(개수·난이도·정답 편향)과 **부족한 자리 순위**를 낸다. 핵심 지표는 **여유 배수 = 은행 문항 수 ÷ 한 판 할당량**이다. 한 판은 분야마다 `top1/high2/mid4/low2/bottom1`을 뽑으므로 이 배수가 작을수록 재도전 때 같은 문제를 다시 만난다. `QUOTA`는 `storage.js`의 `DIFFICULTY_QUOTA`와 같아야 한다 — 갈라지면 이 지표가 거짓말을 한다.
- `tools/backup_bank.py` — `.backups/<타임스탬프>/`에 문항 파일 5개 + `manifest.json`(문항 수·SHA-256). `--list`, `--verify`. 최근 30개만 남긴다. 보관함은 **자기 자신까지 무시하는 `.gitignore`**를 품는다 — `!.gitignore`로 예외를 두면 추적되지 않은 파일이 남아 폴더가 `git status`에 노출된다.

**시험 삼아 돌리다 진짜 문제를 찾았다.** 진단이 1순위로 고른 한국사 `최하`에 4문항을 넣으려 하자 `--dry-run`이 **90개 id가 밀린다**고 알렸고, 그중 `KH-032` `KH-093` `KH-087` 등 **CLAUDE.md 사후 수정 이력이 가리키던 문항 참조가 대부분 진짜**였다(과학 `상`에 넣었을 때는 전부 오탐이었다). 은행을 건드리지 않고 4단계에서 멈췄다.

원인은 파일이 `bottom → top` 순이라 **쉬운 난이도일수록 뒤에 밀 문항이 많다**는 것이다. 같은 분야에서 `최하`는 90개, `최상`은 0개가 밀린다. 여유 배수만 보면 둘이 똑같이 10.0배라 **비용이 보이지 않았다.**

그래서 `bank_report.py --targets`에 **`밀림` 칸**을 세우고, 1순위의 밀림이 60 이상이면 더 싼 대안을 함께 제시하게 했다. 판단 기준은 이렇다 — 할당량 미달이면 비용과 무관하게 먼저 채우고, 여유 배수가 같고 밀림만 다르면 **밀림이 작은 쪽**을 고르며, 꼭 그 자리여야 하면 넣되 **문서 참조를 전부 고친다.**

> 교훈: **"부족한 곳"과 "넣기 싼 곳"은 다르다.** id를 파일 순서에 묶어 둔 설계의 대가이며, 문서가 id로 문항을 지목하는 한 계속 따라온다.

## 유지보수 지점

- **배점을 바꾸고 싶다** → `game.js`의 `POINTS_BY_DIFFICULTY` 한 곳만. 뱃지 색은 `css/style.css`의 `.question-points[data-tier=...]`.
- **은행이 어떤 상태인지 보고 싶다** → `/quiz-stats`(분포·편향) / `/quiz-range`(번호 구간) / `/quiz-validate`(문항 내용).
- **문항만 늘리고 싶다** → `/quiz-add <분야> <난이도> <개수>`가 작성·삽입·검증을 한 줄기로 진행한다. 손으로 넣으려면 `data/questions/<분야>.js`만 고치고 `python3 tools/validate_bank.py`. **검증기는 내용의 옳고 그름도, 정답 위치 쏠림도 보지 못하므로**, 아래 「퀴즈 문제 교차 검증 가이드라인」 4가지와 `answerIndex` 분포는 사람이 직접 확인해야 한다.
  - 난이도 구간 중간에 넣으면 **뒤쪽 id가 통째로 밀린다.** `tools/insert_questions.py`가 재부여와 머리말 갱신을 맡으니 손으로 번호를 고치지 말 것.
- **난이도 비율을 바꾸고 싶다** → `storage.js`의 `DIFFICULTY_QUOTA`(합이 10이어야 함) + `validate_bank.py`의 같은 상수. 은행 구성까지 바꾸려면 `validate_bank.py`의 `EXPECTED_BANK_MIX`도 — **분야별 표**라 분야마다 따로 적는다.
- **디자인만 바꾸고 싶다** → `css/style.css` + `js/views.js`만. `preview.html`로 확인.
- **제목 문구를 바꾸고 싶다** → `tools/title-svg-generator.py`의 `LINES`/`LABEL` 수정 후 `--inject`. `index.html`의 마커 사이를 손으로 고치지 말 것.
- **규칙·연출만 바꾸고 싶다** → `js/game.js` + `js/audio.js`만.
- **진짜 배경/BGM/효과음을 넣고 싶다** → `assets/README.md`의 파일명 그대로 넣기만 하면 된다. 코드 수정 불필요. BGM은 4개를 다 넣어야 한다(일부만 넣으면 없는 트랙 차례에 소리가 끊긴다).
- 분야를 추가하려면 `CATEGORIES` + `CATEGORY_ORDER` + `BG_FALLBACK`(views.js) 세 곳을 함께 고쳐야 한다. `validate_bank.py`의 `CATEGORY_ORDER`도 같이.

   : 논란이 있는 내용은 주류가 되는 이론과 정보를 참조할 것
