실행 인수: **$ARGUMENTS**

> 이 하네스는 위치 인수(`$1`)를 신뢰할 수 없다 — 0-based로 밀려 들어온다.
> **`$ARGUMENTS` 한 덩어리만 쓰고 개수·분야는 그 문자열에서 골라낼 것.**

문제 은행을 조금씩 꾸준히 늘리는 루틴이다. `/quiz-add`가 **어디에 넣을지 사람이 정해서** 부르는 명령이라면, 이쪽은 **어디가 부족한지 스스로 진단해서** 채운다.

인수를 비우면 4문항을 추가한다. 숫자를 주면 그만큼(한 번에 10개까지), 분야를 함께 주면 진단을 무시하고 그 분야에 넣는다.

## 이 명령의 규칙 — 7단계, 단계마다 검증, 실패하면 즉시 중단

아래 일곱 단계를 **순서대로** 밟는다. 각 단계 끝에 **검증**이 붙어 있고, 검증에 실패하면 **다음 단계로 넘어가지 않는다.** 실패한 단계 번호와 원인을 보고하고 그 자리에서 멈춘다.

| 단계 | 하는 일 | 실패하면 |
|---|---|---|
| 1 | 파일 구조 파악 + **되돌림 지점 확보** | 중단 |
| 2 | 현재 개수·분포 확인 | 중단 |
| 3 | 카테고리별 부족한 부분 파악 | 중단 |
| 4 | 추가 전 중복 체크 | 중단 (문항을 다시 쓴다) |
| 5 | 추가 후 형식 검증 | **되돌린 뒤** 중단 |
| 6 | 전체 데이터 백업 | 중단 (은행은 이미 정상) |
| 7 | 실행 결과 상세 보고 | — |

**"실패하면 즉시 중단"을 지키려면 되돌릴 수 있어야 한다.** 그래서 6단계의 백업과 별개로, **1단계에서 되돌림 지점을 먼저 잡는다.** 5단계 검증이 깨졌을 때 6단계 백업은 이미 망가진 은행을 담게 되므로 구제책이 되지 못한다. 둘은 목적이 다르다 — 1단계는 **되돌리기 위한** 스냅숏, 6단계는 검증을 통과한 상태를 **보관하기 위한** 스냅숏이다.

## 1단계 — 파일 구조 파악 + 되돌림 지점 확보

```bash
cd quiz-game && echo "── 문항 파일 ──" && ls -la data/questions/ && echo && \
head -8 data/questions/science.js && echo "── 난이도 구간 ──" && \
grep -n "── " data/questions/science.js && echo "── 되돌림 지점 ──" && \
mkdir -p /tmp/quiz-daily-rollback && cp -v data/questions/*.js data/questions.js /tmp/quiz-daily-rollback/
```

읽고 확인할 것:

- 문항은 `data/questions/<분야>.js` 네 파일에 나뉘어 있고 `data/questions.js`가 합쳐 내보낸다
- 파일 안은 **쉬운 것부터 어려운 순**(bottom → low → mid → high → top)으로 모여 있고 id가 그 순서로 붙는다
- 그래서 **중간 난이도에 문항을 넣으면 뒤쪽 id가 통째로 밀린다** — 손으로 하지 말 것
- `category`는 파일 상단 상수 `C`로 묶여 있다

**검증:** 네 파일이 모두 존재하고 되돌림 지점에 5개 파일이 복사됐는가. 하나라도 빠지면 **1단계 실패로 중단.**

## 2단계 — 현재 개수와 분포 확인

```bash
cd quiz-game && python3 tools/bank_report.py
```

분야별 총계, 난이도 5단계 구성, 정답 위치 분포와 χ² 편향 판정을 한 번에 낸다.

**검증:** `validate_bank.py`가 지금 상태에서 통과하는가. **손대기 전에 이미 깨져 있으면 이 명령이 그 원인이 아니므로 손대면 안 된다.**

```bash
cd quiz-game && python3 tools/validate_bank.py
```

하나라도 FAIL이면 **2단계 실패로 중단**하고, 무엇이 어떻게 깨져 있는지 보고한다. 문항을 추가하지 말 것.

## 3단계 — 카테고리별 부족한 부분 파악

```bash
cd quiz-game && python3 tools/bank_report.py --targets
```

**"부족하다"의 기준은 여유 배수 = 은행 문항 수 ÷ 한 판 할당량**이다. 한 판은 분야마다 `최상1 / 상2 / 중4 / 하2 / 최하1`을 뽑으므로, 이 배수가 작은 자리일수록 재도전했을 때 같은 문제를 다시 만나기 쉽다. 그 자리가 곧 채워야 할 곳이다.

순위를 매기는 규칙은 이렇다.

1. **할당량 미달**(예: `상`이 2문항 미만) — 다른 무엇보다 먼저. 샘플링이 인접 난이도 보충 경로를 타서 비율이 흔들린다
2. **여유 배수가 작은 자리**
3. **총계가 작은 분야** — 분야마다 개수가 달라질 수 있다
4. 설계 비율(10:20:40:20:10) 대비 모자란 쪽

### `밀림` 칸을 반드시 함께 볼 것

파일이 `bottom → top` 순으로 정렬돼 있어서 **쉬운 난이도에 넣을수록 뒤쪽 id가 많이 밀린다.** 첫 블록(`최하`)에 넣으면 그 분야의 90문항이 전부 새 번호를 받는다.

id가 밀리면 **CLAUDE.md 사후 수정 이력이 가리키던 문항이 어긋난다.** 이 문서는 `KH-093은 보기 두 개가 같은 것을 가리키고 있었다`처럼 id로 문항을 지목하므로, 밀린 뒤에는 엉뚱한 문항을 가리키게 된다.

그래서 여유 배수가 같다면 **`밀림`이 작은 자리를 고르는 편이 싸다.** 스크립트도 1순위의 밀림이 60 이상이면 더 싼 대안을 함께 알려 준다.

| 상황 | 판단 |
|---|---|
| 할당량 미달 | 비용과 무관하게 **먼저 채운다** |
| 여유 배수가 같고 밀림만 다르다 | **밀림이 작은 쪽**을 고른다 |
| 꼭 그 자리에 넣어야 한다 | 넣되 **5단계에서 문서 참조를 전부 고친다** |

문서 참조를 고칠 때는 **진짜 참조와 오탐을 갈라야 한다.** `SC-001 ~ SC-100` 같은 범위 표기나 명령어 문서의 예시는 문항을 가리키지 않으므로 손대지 않는다.

**검증:** 1순위 자리가 나왔는가. 할당량 미달이 있으면 스크립트가 종료 코드 1로 알리고 **그 자리를 먼저 채우라고** 말한다. 사용자가 분야를 지정했으면 진단보다 지정을 따르되, **진단 결과를 함께 보여 주고** 다르면 그 사실을 밝힌다.

## 4단계 — 새 문항 추가 전 중복 체크

먼저 대상 분야의 기존 문항을 **질문과 정답까지** 훑는다. 중복 판정 기준은 문장이 아니라 **묻는 대상**이다.

```bash
cd quiz-game && python3 - "<분야 stem>" <<'PY'
import re, sys
OBJ = re.compile(r"  \{\n    id: '([^']+)',\n(.*?)\n  \},", re.S)
Q   = re.compile(r"\n    question: (\"(?:[^\"\\]|\\.)*\"|'(?:[^'\\]|\\.)*')")
A   = re.compile(r"\n    choices: \[(.*?)\],\n", re.S)
S   = re.compile(r"\"((?:[^\"\\]|\\.)*)\"|'((?:[^'\\]|\\.)*)'")
src = open(f'data/questions/{sys.argv[1]}.js', encoding='utf-8').read()
for m in OBJ.finditer(src):
    b = m.group(2)
    ch = [x or y for x, y in S.findall(A.search(b).group(1))]
    ans = int(re.search(r"answerIndex: (\d)", b).group(1))
    d = re.search(r"difficulty: '(\w+)'", b).group(1)
    print(f"{m.group(1)} [{d:6}] {Q.search(b).group(1)[1:-1]}  → {ch[ans]}")
PY
```

- ❌ `한글을 창제한 왕은?` vs `훈민정음을 반포한 왕은?` — 표현만 다르고 소재도 답도 같다
- ⭕ `세종이 만든 천문 기구는?` — 소재가 겹쳐도 **묻는 각도가 다르면** 다른 문항이다

인물·사건은 분야를 넘나드니 미심쩍으면 은행 전체를 훑는다.

```bash
cd quiz-game && grep -rn "핵심어1\|핵심어2" data/questions/ | grep question
```

그다음 문항을 쓴다. **CLAUDE.md 「퀴즈 문제 교차 검증 가이드라인」 4가지를 지킨다.**

1. 정답이 하나뿐인가 — 다른 해석이 가능하면 조건을 명시(`면적 기준`)
2. 최상급 표현에 기준이 있는가 — `가장 큰`을 쓰려면 무엇을 기준으로 한 것인지
3. 시간·범위가 명확한가 — 변할 값은 시점을, 한정되는 범위는 그 범위를
4. 사실이 맞는가 — 자명하지 않으면 **WebSearch로 출처 2개 이상**

**이 프로젝트가 실제로 데인 자리 넷을 다시 밟지 말 것.**

- **범위 밖 보기** — `삼국 가운데`라면서 보기에 가야·발해 (KH-004, KH-032)
- **같은 것을 가리키는 보기 둘** — `이벌찬`과 `각간`. 문자열이 달라 자동 검사를 통과한다 (KH-093)
- **잣대가 갈리는 최상급** — `가장 넓은 면적의 기관`은 피부가 아니라 소장 (SC-012)
- **다른 잣대의 정답이 보기에 섞임** — `처음` 선 임시정부는 시기로는 블라디보스토크 (KH-009)

정답 위치는 **0~3번에 고르게, 연달아 같은 번호가 오지 않게** 배치한다. 2단계에서 본 χ²에 편향이 있었다면 **모자란 번호 쪽으로 몰아 준다.** 네 보기가 모두 숫자면 섞지 말고 **오름차순**을 유지한다.

JSON 배열로 스크래치패드에 쓴다. `id`·`category`·`difficulty`는 적지 않는다 — 스크립트가 채운다.

```json
[{ "question": "...", "choices": ["","","",""], "answerIndex": 0, "explanation": "..." }]
```

**검증:** `--dry-run`으로 중복·스키마 검사를 통과하는가.

```bash
cd quiz-game && python3 tools/insert_questions.py <분야> <난이도> <새문항.json> --dry-run
```

거부되면 **4단계 실패**다. 문항을 고쳐 다시 검사한다 — 은행은 아직 손대지 않았으므로 되돌릴 것이 없다. 사용자에게 문항을 보이고 승인을 받은 뒤에만 5단계로 간다.

## 5단계 — 문제 추가 후 형식 검증

```bash
cd quiz-game && python3 tools/insert_questions.py <분야> <난이도> <새문항.json>
```

이어서 **세 가지를 모두** 확인한다.

```bash
cd quiz-game && python3 tools/validate_bank.py
```

```bash
cd quiz-game && python3 tools/bank_report.py
```

그리고 새로 넣은 구간만 따로 본다 — `/quiz-range <분야> <첫 번호> <끝 번호>`.

**검증 항목:**

- `validate_bank.py` 전 항목 PASS (21건)
- 새 구간의 난이도가 전부 요청한 값인가
- 새 구간의 정답 위치가 한쪽으로 몰리지 않았는가
- 밀린 id가 문서를 어긋나게 하지 않는가 — 스크립트가 짚어 주지만 **`SC-001 ~ SC-100` 같은 범위 표기는 오탐**이므로 사람이 가른다

**하나라도 실패하면 되돌리고 중단한다.**

```bash
cd quiz-game && cp /tmp/quiz-daily-rollback/*.js data/questions/ && \
mv data/questions/questions.js data/questions.js && python3 tools/validate_bank.py
```

되돌린 뒤 `validate_bank.py`가 다시 통과하는지까지 확인하고 나서 보고한다.

## 6단계 — 전체 데이터 백업

검증을 통과한 상태만 보관한다.

```bash
cd quiz-game && python3 tools/backup_bank.py && python3 tools/backup_bank.py --verify $(ls quiz-game/.backups 2>/dev/null | tail -1)
```

`.backups/<타임스탬프>/`에 문항 파일 5개와 `manifest.json`(문항 수 + SHA-256)을 담는다. 최근 30개만 남기고 오래된 것은 지운다. 폴더는 자체 `.gitignore`로 git에 올라가지 않는다.

**검증:** `--verify`가 스냅숏과 현재 은행이 같다고 확인해 주는가. 다르면 **6단계 실패** — 다만 이때 은행 자체는 이미 5단계를 통과한 정상 상태이므로 되돌리지 말고, 백업만 다시 시도한다.

보관된 목록은 `python3 tools/backup_bank.py --list`로 본다.

- **단계마다 한 줄씩** 무엇을 확인했는지 남긴다. "통과"만 쓰지 말고 **근거 수치**를 적는다.

- 밀린 id가 있으면 범위와 문서 영향(진짜/오탐)을 밝힌다.
- **실패로 중단했으면** 실패한 단계 번호, 검증에서 무엇이 어긋났는지, 되돌렸는지 여부를 먼저 쓴다. 나머지 단계는 "미실행"으로 남긴다.

- 문항이 늘어도 **한 판은 여전히 40문제**다. 늘어난 만큼 재도전 시 덜 겹칠 뿐이다.
- 여러 문항을 넣었거나 id가 밀렸으면 `CLAUDE.md`의 "사후 수정 이력"에 남긴다.
