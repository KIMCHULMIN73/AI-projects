> 이 문서는 Claude Code에서 프롬프트로 사용하도록 작성되었습니다.
> 유지보수를 쉽게 하기 위해 **데이터(모듈 1) / 화면(모듈 2) / 로직·사운드(모듈 3)**
> 세 개의 독립 모듈로 나누어 설계했으며, 각 모듈은 §9에 붙여넣기용 프롬프트로 정리되어 있습니다.

## 1. 제품 개요

한 화면에서 진행되는 4지선다 상식 퀴즈 게임. 도전자는 한국사·과학·세계지리·예술/문화/시사
네 분야에서 각 10문제씩 총 40문제를 풀며, 정답·오답에 따라 점수가 오르내린다.
게임이 끝나면 성적 요약과 함께 지금까지 도전한 모든 사람의 랭킹을 보여준다.

핵심 재미 요소: 화려한 정답/오답 팝업과 효과음, 분야별로 바뀌는 배경, 세계여행 느낌의
경쾌한 BGM, 그리고 누적 랭킹 경쟁.

---

## 2. 대상 사용자 & 난이도 기준

- 대상: 대한민국 고등학교 졸업 수준의 일반인.
- 문제는 그 수준에서 풀 수 있는 상식 범위 안에서 출제하되, 아래 비율로 난이도를 섞는다.

| 난이도 | 비율 | 분야당(10문제) | 전체(40문제) |
|---|---|---|---|
| 최상 | 10% | 1 | 4 |
| 상 | 20% | 2 | 8 |
| 중 | 50% | 5 | 20 |
| 하 | 20% | 2 | 8 |

---

## 3. 게임 규칙

- 초기 점수: **100점**.
- 문제당 4지선다(객관식).
- 정답: **+10점**, 오답: **−10점**.
- 총 40문제(분야별 10문제).
- 각 문제는 정답 처리 직후 **해설**을 함께 제공한다.
- 문제 은행에는 40문제보다 많은 문항을 보유하고, 게임을 시작할 때마다
  분야별로 §2의 난이도 비율을 지켜 10문제씩 무작위 샘플링해 출제한다(재도전 시 문제가 바뀜).

## 4. 화면 정의

공통 레이아웃: **화면 전체를 채우는 분야별 배경 이미지** 위에, 화면 중앙에
**모서리가 둥근 흰색 박스(패널)** 를 얹고 그 안에 모든 콘텐츠를 배치한다.

### 4-1. 시작 화면 (Start)
- 최상단: 제목 **"누가누가 잘하나 좌충우돌 퀴즈게임"** — VT323 폰트.
- 제목 앞: **사격 과녁(🎯) 아이콘**을 크게 배치.
- 제목 아래: 출제 4개 분야를 **아이콘 + 제목의 카드**로 나열.
  - 한국사 상식 🏯 / 과학 상식 🔬 / 세계지리 상식 🌍 / 예술·문화·시사 🎨
- 그 아래: **도전자 이름 입력창** + **게임 시작 버튼**.
  - 이름이 비어 있으면 시작 버튼 비활성화(또는 경고).

### 4-2. 게임 화면 (Play)
- 시작 버튼을 누르면 화면이 전환된다.
- 상단 바(항상 표시): **도전자 이름 / 진행률(현재 푼 문제 수 ÷ 전체 40) / 현재 점수**.
- 본문: 현재 분야에 맞는 배경 위에서 문제 텍스트 + 4개 보기 버튼.
- 문제의 분야가 바뀌면 배경 이미지도 해당 분야 배경으로 전환된다.

### 4-3. 피드백 (Feedback)
- 보기를 고르면 **즉시** 정답/오답을 알려준다.
- **화려한 팝업**(정답/오답 각각 다른 색·애니메이션) + **효과음**.
- 팝업 안에 해당 문제의 **해설** 표시.
- "다음 문제" 진행.

### 4-4. 완료 화면 (Result)
- **트로피(🏆) 아이콘** + **"게임 종료"** 제목을 크게 표시.
- 최종 점수 / 전체 문항 대비 정답 수 / 정답률(%).
- **분야별 정답률** 표시(4개 분야).
- **다시 도전** / **종료** 버튼.

### 4-5. 랭킹 화면 (Ranking)
- 완료 화면에서 **종료**를 누르면 진입.
- 지금까지 도전한 **모든 사람의 기록**을 **순위 / 이름 / 점수**로 정렬해 보여준다.
- (다시 시작하기 버튼 제공 → 시작 화면으로.)

## 6. 비기능 요구사항

- **성능**: 최초 로드 후 화면 전환·채점은 체감 지연 없이 즉시.
- **호환성**: 최신 크롬/엣지/사파리 데스크톱 기준. 최대 화면 크기(전체 화면) 기준 레이아웃.
- **견고성**: `localStorage` 접근은 항상 try/catch로 감싸 실패해도 게임은 진행되게 한다.
- **유지보수성**: 3개 모듈은 서로의 내부 구현을 모르고, 아래 §9의 **인터페이스(계약)** 로만 통신한다.
- **오디오 정책**: 브라우저 자동재생 정책상 BGM은 첫 사용자 상호작용(시작 버튼 클릭) 이후 재생.

```js

  category: "korean_history",         // korean_history | science | world_geography | arts_culture

  explanation: "정답 해설 텍스트"

```

```js
{
  name: "철민",
  score: 130,
  correctCount: 28,
  total: 40,

    world_geography: 0.7,
    arts_culture: 0.7

  playedAt: "2026-07-31T09:00:00.000Z"

```

## 8. 에셋 정책

```
assets/
  bg/
    start.jpg                 # 시작 화면 배경
    korean_history.jpg
    science.jpg
    world_geography.jpg
    arts_culture.jpg
  bgm/
    travel1.mp3 ~ travel4.mp3 # 세계여행풍 경쾌 BGM(로테이션)

    correct.mp3               # 정답 효과음
```

- 배경/BGM/효과음은 **로열티 프리** 에셋으로 미리 배치(고정 사용 허용).
- BGM은 배열로 관리하여 **문제(또는 분야) 전환마다 다음 트랙으로 순환** 재생.
- 문제 은행만은 §9 모듈 1에서 지속적으로 확장(업데이트)한다.

## 9. 모듈화 설계 — 독립적 3단계

> 아래 세 프롬프트를 **순서대로** Claude Code에 입력한다.
> 각 모듈은 명시된 **인터페이스(계약)** 만 지키면 서로 독립적으로 수정·교체·테스트할 수 있다.

### 파일 구조(최종)
```
quiz-game/
  index.html
  css/
    style.css
  data/
    questions.js        # [모듈1] 문제 은행 DB
  js/
    storage.js          # [모듈1] 샘플링 + 랭킹 저장/조회
    views.js            # [모듈2] 화면 렌더링 함수
    audio.js            # [모듈3] BGM/효과음
    game.js             # [모듈3] 게임 상태머신
    main.js             # [모듈3] 부팅 & 모듈 연결
```

### 모듈 간 계약(인터페이스) 요약

- **모듈2 → 노출**: `Views.showStart()`, `Views.showQuestion(q, state)`, `Views.showFeedback(...)`, `Views.showResult(summary)`, `Views.showRanking(list)`, `Views.setBackground(category)`
- **모듈3**: 위 두 모듈을 import 해 게임 흐름을 구동. 모듈1·2는 모듈3을 몰라도 됨.

### ▶ 모듈 1 — 데이터 계층 (문제 은행 DB + 랭킹 저장소)

```
프레임워크 없는 Vanilla JS(ES Modules)로 상식 퀴즈 게임의 "데이터 계층"만 먼저 만들어줘.
UI/사운드는 이 단계에서 절대 건드리지 마. 콘솔에서 단독 테스트 가능한 순수 데이터/로직 모듈이야.

[파일 1] data/questions.js
- 문제 은행(QUESTION_BANK) 배열을 export.
- 문제 객체 스키마:
  { id, category, difficulty, question, choices:[4개], answerIndex:0~3, explanation }
- category 값: "korean_history" | "science" | "world_geography" | "arts_culture"
- difficulty 값: "top"(최상) | "high"(상) | "mid"(중) | "low"(하)
- 분야별로 최소 15문항 이상 채워줘(총 60문항 이상). 그래야 게임마다 문제가 바뀔 수 있어.
- 각 분야 안에서 난이도 분포는 최상:상:중:하 = 대략 1:2:5:2 이상 나오도록 골고루 넣어줘.
- 수준: 대한민국 고졸 일반인이 풀 수 있는 상식 범위. 모든 문제에 한 줄 이상 해설 필수.
- 파일 맨 위에 "새 문항 추가 방법"을 주석으로 5줄 이내로 적어줘(계속 업데이트할 거라서).
- CATEGORIES 상수도 export: 각 category의 표기명(라벨)과 아이콘(이모지) 매핑.
  예: { korean_history: {label:"한국사 상식", icon:"🏯"}, ... science 🔬, world_geography 🌍, arts_culture 🎨 }

[파일 2] js/storage.js
- getQuizSet()를 export: QUESTION_BANK에서 분야별로 10문제씩 총 40문제를 뽑아 반환.
  · 분야당 난이도 비율을 최상1/상2/중5/하2로 맞춰 샘플링(해당 난이도 부족 시 인접 난이도로 보충).
  · 같은 문제 중복 없이 무작위 셔플. 반환 배열은 분야 순서대로(한국사→과학→세계지리→예술) 정렬.
- Storage.saveRecord(record)를 export: localStorage 키 "quiz.rankings" 배열에 기록 추가.
  record 스키마: { name, score, correctCount, total, accuracy, byCategory, playedAt }
- Storage.getRankings()를 export: 저장된 기록을 점수 내림차순 정렬해 반환(동점이면 최신순).
- localStorage 접근은 전부 try/catch로 감싸고, 실패해도 앱이 안 죽게 빈 배열/무시로 처리.

[검증] 파일 하단에 주석으로 콘솔 테스트 예시를 남겨줘:
  getQuizSet()가 40개(분야별 10개, 난이도 비율 근사)를 반환하는지,
  saveRecord→getRankings가 정렬되어 나오는지 확인하는 코드.
```

**모듈 1 완료 기준**: `getQuizSet()`가 분야별 10문제·난이도 비율을 지켜 40문제를 반환하고,
랭킹 저장/조회가 정렬되어 동작한다. UI·사운드 코드는 전혀 없다.

### ▶ 모듈 2 — 화면 & 스타일 (Views + Layout + Assets)

```
모듈1(data/questions.js, js/storage.js)이 완성된 프로젝트에 이어서,
"화면(View) 계층"만 만들어줘. 게임 로직/사운드는 넣지 말고, 정적으로 렌더되는 화면과 스타일만.

[공통 레이아웃]
- 화면 전체를 채우는 배경 이미지 위에, 화면 중앙에 모서리가 둥근 흰색 박스(.panel)를 얹어.
  그 흰 박스 안에서 모든 콘텐츠를 그려. 최대 화면(전체 화면) 기준으로 반응형.
- 배경 이미지는 assets/bg/ 에 있다고 가정(start, korean_history, science, world_geography, arts_culture).

[index.html]
- 화면 4개 컨테이너를 만들고 하나만 보이게(나머지 hidden): #screen-start, #screen-play, #screen-result, #screen-ranking.
- Google Fonts VT323 로드(<link>). 제목에 쓸 거야.

[css/style.css]
- 제목 "누가누가 잘하나 좌충우돌 퀴즈게임"은 VT323 폰트로 크게, 도트매트릭스 느낌.
- 시작 화면: 제목 앞에 사격 과녁 아이콘 🎯 크게. 그 아래 분야 4개를 아이콘+제목 "카드"로.
  (CATEGORIES의 label/icon 사용) 그 아래 도전자 이름 입력창 + 게임 시작 버튼.
- 게임 화면: 상단 바에 [도전자 이름] [진행률: 현재/40] [점수] 배치. 아래에 문제 텍스트 + 보기 4버튼.
- 피드백 팝업: 정답용/오답용 각각 다른 색과 등장 애니메이션(화려하게). 팝업 안에 해설 영역.
- 완료 화면: 트로피 🏆 아이콘 + "게임 종료" 크게. 최종점수/정답수/정답률/분야별 정답률 표시 영역.
  아래에 [다시 도전] [종료] 버튼.
- 랭킹 화면: 순위 / 이름 / 점수 테이블. 아래에 [다시 시작하기] 버튼.

[js/views.js] — 순수 렌더 함수만 export(로직 없음, 데이터는 인자로 받음):
- Views.showStart()                         : 시작 화면 표시(다른 화면 숨김)
- Views.setBackground(category)             : body/배경을 해당 분야(또는 "start") 이미지로 전환
- Views.showQuestion(q, state)              : 문제/보기 렌더. state={name, index, total, score}로 상단바 갱신
- Views.showFeedback(isCorrect, explanation): 정답/오답 팝업 + 해설 표시(효과음 호출은 하지 않음)
- Views.showResult(summary)                 : summary={score, correctCount, total, accuracy, byCategory}
- Views.showRanking(list)                   : [{name, score}] 정렬 목록을 순위와 함께 표시
- 보기 버튼 클릭 등 이벤트는 여기서 처리하지 말고, 콜백을 인자로 받거나 버튼에 data-index만 부여해
  둬(실제 바인딩은 모듈3이 함). View는 "그리기"만 담당.

[검증] 임시 더미 데이터로 각 show* 함수를 한 번씩 호출해 4개 화면이 의도대로 보이는지 확인.
```

**모듈 2 완료 기준**: 더미 데이터만으로 시작/게임/완료/랭킹 4개 화면이 정상 렌더되고,
분야별 배경 전환·흰색 둥근 박스·VT323 제목·과녁/트로피 아이콘이 요구대로 보인다.

### ▶ 모듈 3 — 게임 로직 & 사운드 (Controller + Audio)

```
모듈1(데이터)과 모듈2(뷰)가 있는 프로젝트에 이어서, 둘을 연결하는 "게임 로직 + 사운드"를 만들어줘.
모듈1/2의 인터페이스만 사용하고 그 내부는 수정하지 마.

[js/audio.js]
- 세계여행 느낌의 경쾌한 BGM을 배열로 관리(assets/bgm/travel1~4.mp3). 문제(또는 분야) 전환마다
  다음 트랙으로 순환 재생. 첫 재생은 시작 버튼 클릭 이후에(자동재생 정책 대응).
- Audio.playCorrect(), Audio.playWrong() : 정답/오답 효과음(assets/sfx/).
- Audio.startBgm(), Audio.stopBgm(), Audio.nextBgm() export.

[js/game.js] — 게임 상태머신을 export:
- 상태: START → PLAYING(문제 출제) → FEEDBACK(채점/해설) → ... → RESULT → RANKING.
- 시작: 도전자 이름을 받고 getQuizSet()으로 40문제를 로드. 점수는 100에서 시작. index=0.
- 문제 진행: 현재 문제의 category로 Views.setBackground 호출 + Audio.nextBgm().
  Views.showQuestion(q, {name, index, total:40, score}) 렌더.
- 채점: 보기 선택 시 정답이면 +10/오답이면 -10. Audio.playCorrect/Wrong + Views.showFeedback(정답여부, 해설).
  분야별 정답/오답 카운트를 누적.
- 완료: 40문제 종료 시 summary 계산(최종점수, correctCount, accuracy, byCategory 정답률) → Views.showResult.
  · [다시 도전] → 문제 재샘플링해서 처음부터(같은 이름 유지, 점수 100 리셋).
  · [종료] → Storage.saveRecord(record) 후 Storage.getRankings()로 Views.showRanking 호출, Audio.stopBgm.

[js/main.js]
- DOMContentLoaded 시 Views.showStart()로 부팅.
- 시작 버튼/보기 버튼/다시도전/종료/다시시작 버튼의 이벤트를 여기서 game.js에 연결(이벤트 위임 권장).
- index.html 하단에서 main.js를 type="module"로 로드.

[검증] 아래 시나리오를 직접 확인:
1) 이름 입력 후 시작 → 100점에서 출발, 분야별 배경이 바뀌며 40문제가 순서대로 나온다.
2) 정답 +10/오답 -10이 점수와 상단 진행률(n/40)에 즉시 반영, 팝업+효과음+해설이 뜬다.
3) 40문제 종료 → 트로피 화면에 최종점수/정답수/정답률/분야별 정답률이 정확히 표시.
4) 다시 도전 시 문제가 새로 샘플링된다. 종료 시 랭킹에 이름/점수/순위가 정렬되어 추가·표시된다.
5) 새로고침해도 랭킹 기록이 유지된다(localStorage).
```

**모듈 3 완료 기준**: §4 화면 흐름 전체가 끊김 없이 동작하고, 채점·해설·BGM·랭킹 저장까지 통합 완료.

## 10. 빌드 순서 & 통합 검증

1. **모듈 1**(데이터) → 콘솔로 샘플링/랭킹 저장 검증.

**규칙·연출만 바꾸고 싶을 땐 모듈3**만 손대면 되어 유지보수가 분리된다.
