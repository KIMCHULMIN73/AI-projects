# 데일리 할 일 관리 앱 — Claude Code 단계별 프롬프트

> PRD(v1.0)를 Claude Code에서 실행할 5단계 개발 프롬프트로 변환한 문서입니다.
> **순서대로** 진행하세요. 각 단계는 이전 단계의 결과물 위에 기능을 얹는 구조입니다.
> 각 단계 프롬프트는 회색 코드블록 안의 내용을 그대로 복사해 Claude Code에 붙여넣으면 됩니다.

---

## 전체 기술 제약 (모든 단계 공통)

Claude Code가 매 단계에서 지켜야 할 원칙입니다. 각 프롬프트에도 요약되어 있지만, 첫 단계에서 한 번 못박아 두세요.

- 순수 **HTML5 + CSS3 + Vanilla JavaScript (ES6+)** 만 사용
- **외부 라이브러리·프레임워크·빌드 도구 금지** (npm, React, Tailwind CDN 등 X)
- 브라우저에서 `index.html`을 **여는 것만으로 실행**되어야 함
- 데이터는 **localStorage** 에만 저장 (서버·DB 없음)
- 파일 구성: `index.html`, `style.css`, `app.js` 세 개로 분리

## 1단계 · 프로젝트 구조와 화면 레이아웃

**목표:** 데이터 로직 없이, PRD의 화면 구성(헤더 / 입력 / 필터 / 목록)을 담은 정적 뼈대와 스타일을 먼저 만든다.

```
데일리 할 일 관리 웹 앱을 만들려고 한다. 이번 단계에서는 로직 없이 화면 구조와 스타일만 잡아줘.

[기술 제약]
- 순수 HTML5, CSS3, Vanilla JavaScript(ES6+)만 사용
- 외부 라이브러리·프레임워크·빌드 도구 절대 사용 금지
- index.html을 브라우저에서 여는 것만으로 실행돼야 함
- 파일을 index.html, style.css, app.js 3개로 분리하고, index.html에서 css와 js를 연결까지 해줘

[이번 단계에서 만들 화면 구성 (위에서부터)]
1. 헤더: 앱 제목 "오늘의 할 일" + 진행률 바 영역(빈 프로그레스 바) + "완료 0 / 전체 0" 텍스트
2. 입력 영역: 할 일 텍스트 입력창 + 카테고리 선택(업무/개인/공부) + "추가" 버튼
3. 필터 탭: 전체 / 업무 / 개인 / 공부
4. 목록 영역: 할 일 항목이 들어갈 빈 컨테이너(지금은 비어 있어도 됨)

[스타일 요구]
- 깔끔하고 모던한 디자인, 카드 형태의 중앙 정렬 레이아웃(최대 폭 600px 정도)
- 카테고리 3종(업무/개인/공부)에 각각 구분되는 색상을 CSS 변수로 정의
- 데스크톱 기준으로 만들되 모바일에서도 깨지지 않게 반응형 고려

app.js는 아직 비워두거나 최소한의 뼈대만 둬. 이번 단계 완료 후 어떤 구조로 파일을 나눴는지 요약해줘.
```

## 2단계 · 데이터 모델과 localStorage 영속화

**목표:** 앱의 심장인 데이터 계층을 먼저 구축한다. 화면 렌더링은 최소로, "데이터를 읽고/저장하는" 기반을 확실히 만든다.

```
1단계에서 만든 앱에 데이터 모델과 localStorage 저장 기능을 추가해줘. 아직 UI 상호작용(추가 버튼 등)은 연결하지 않아도 되고, 데이터 계층을 먼저 탄탄히 만드는 게 목표다.

[데이터 모델]
할 일 하나는 아래 구조의 객체로 표현하고, 전체는 배열로 관리한다.
- id: 고유 식별자 (Date.now() 등 timestamp 기반)
- title: 할 일 제목 (문자열)
- category: 'work' | 'personal' | 'study' 중 하나
- completed: 완료 여부 (boolean, 기본 false)
- createdAt: 생성 시각 (정렬용 숫자)

[localStorage 요구]
- 저장 키는 'todos-app-v1' 로 고정
- 전체 배열을 JSON.stringify 해서 저장하는 saveTodos() 함수
- 페이지 로드 시 localStorage에서 읽어와 JSON.parse 하는 loadTodos() 함수
- 저장된 데이터가 없거나 파싱에 실패해도 앱이 멈추지 않도록 try/catch로 예외 처리하고 빈 배열로 안전하게 시작
- 데이터가 바뀌는 모든 동작 후에는 반드시 saveTodos()가 호출되도록 설계

[검증용 임시 렌더링]
- 현재 todos 배열을 목록 영역에 단순 텍스트로 그려주는 renderTodos() 함수를 만들어줘
- 페이지 로드 시 loadTodos() → renderTodos() 순으로 실행되게 해줘

완료 후, 브라우저 콘솔에서 데이터가 어떻게 저장·복원되는지 확인하는 방법을 알려줘.
```

## 3단계 · 핵심 CRUD (추가 · 수정 · 삭제)

**목표:** PRD의 F-1, F-2, F-3. 사용자가 할 일을 실제로 추가·수정·삭제하고, 그 결과가 저장되도록 UI와 데이터를 연결한다.

```
2단계에서 만든 데이터 계층 위에, 할 일 추가/수정/삭제 기능을 UI와 연결해줘. 모든 변경은 즉시 localStorage에 저장돼야 한다.

[F-1 추가]
- 입력창에 제목을 쓰고 "추가" 버튼 클릭 또는 Enter 키로 새 할 일 등록
- 등록 시 선택된 카테고리를 함께 저장, 미선택이면 기본값 'personal'
- 빈 문자열이나 공백만 입력한 경우 등록을 막고 입력창에 포커스 유지
- 추가 후 입력창은 비우고, 새 항목이 목록에 즉시 표시

[F-2 수정]
- 할 일 제목을 더블클릭하거나 수정 아이콘을 눌러 편집 모드로 전환
- 편집 중 Enter로 저장, Esc로 취소
- 카테고리도 변경 가능하게

[F-3 삭제]
- 각 항목에 삭제(X) 버튼을 두고, 클릭 시 해당 항목을 배열과 화면, 저장 데이터에서 함께 제거

[렌더링]
- renderTodos()를 개선해서 각 항목을 실제 UI(체크박스 자리, 제목, 카테고리 라벨, 수정/삭제 버튼)로 그려줘
  (체크박스 동작은 다음 단계에서 붙일 예정이니 자리만 잡아두면 됨)
- 추가/수정/삭제 등 배열이 바뀔 때마다 renderTodos()와 saveTodos()가 함께 호출되도록

완료 후 각 기능이 어느 함수에서 처리되는지 간단히 정리해줘.
```

## 4단계 · 완료 체크 · 카테고리 라벨 · 필터

**목표:** PRD의 F-4, F-5. 완료 상태 토글과 카테고리 시각화, 그리고 카테고리별 필터링을 완성한다.

```
3단계 앱에 완료 체크와 카테고리 필터 기능을 추가해줘.

[F-4 완료 체크]
- 각 항목 앞 체크박스 클릭으로 완료/미완료 상태를 토글
- 완료된 항목은 취소선 + 흐린 색으로 시각적으로 구분
- 상태 변경 즉시 저장(saveTodos)

[F-5 카테고리 표시]
- 각 항목에 해당 카테고리(업무/개인/공부)를 색상 라벨(뱃지)로 표시
- 라벨 색은 1단계에서 정의한 카테고리별 CSS 변수를 재사용

[카테고리 필터]
- 상단 필터 탭(전체 / 업무 / 개인 / 공부) 클릭 시 해당 카테고리 항목만 목록에 표시
- 현재 선택된 필터 탭은 활성화 상태로 시각 표시
- 필터는 화면 표시만 바꾸는 것이고, 데이터 자체는 삭제하지 않도록 주의
- 필터가 걸린 상태에서 할 일을 추가/수정/삭제해도 올바르게 동작해야 함

렌더링 로직에서 "현재 필터 값"을 어떻게 반영하는지 완료 후 설명해줘.
```

## 5단계 · 진행률 표시 · 마무리 · 검증

**목표:** PRD의 F-6과 F-8, 비기능 요구사항을 마무리한다. 진행률을 완성하고 전체 동작을 점검한다.

```
마지막 단계다. 진행률 표시를 완성하고 앱 전체를 다듬어줘.

[F-6 진행률]
- 전체 할 일 중 완료된 비율을 헤더의 프로그레스 바와 퍼센트(%)로 표시
- "완료 n / 전체 m" 수치도 함께 갱신
- 할 일이 하나도 없을 때는 0%로 표시하고 목록 영역에 "할 일을 추가해보세요" 같은 안내 문구 노출
- 추가/수정/삭제/완료체크 등 상태가 바뀔 때마다 진행률이 실시간으로 정확히 갱신
  (진행률은 필터와 무관하게 '전체' 기준으로 계산)

[F-8 완료 항목 일괄 삭제 — Should]
- "완료 항목 지우기" 버튼을 두고, 완료된 항목을 한 번에 제거

[마무리 및 품질 점검]
- 전체 코드에서 localStorage 접근을 try/catch로 감싸 안전한지 재확인
- 키보드 조작(추가 Enter, 수정 Enter/Esc)이 잘 되는지 확인
- 색 대비와 여백을 다듬어 가독성 개선
- 최종 파일 구조(index.html, style.css, app.js)와 각 파일 역할을 정리

[최종 검증 시나리오 — 아래를 직접 확인하고 결과를 알려줘]
1. 할 일 여러 개를 카테고리별로 추가 → 목록·진행률 정상 표시되는가
2. 몇 개 완료 체크 → 진행률 % 정확히 갱신되는가
3. 필터 탭 전환 → 해당 카테고리만 보이는가
4. 새로고침(F5) → 입력한 데이터가 그대로 유지되는가  ← 가장 중요
5. 수정·삭제 후에도 저장이 유지되는가
```

## 사용 팁

- **한 단계씩** 진행하고, 각 단계가 정상 동작하는지 브라우저에서 확인한 뒤 다음으로 넘어가세요. 문제를 조기에 잡을 수 있습니다.
- 특정 단계 결과가 기대와 다르면, 그 단계 프롬프트 아래에 "이런 점이 안 된다"고 이어서 요청하면 됩니다.
- 4번 검증 시나리오(**새로고침 후 데이터 유지**)가 이 앱의 핵심 요구사항이니 5단계에서 반드시 통과하는지 확인하세요.
- 모든 단계가 끝난 뒤 "전체 코드를 한 번 리뷰하고 중복이나 개선점을 정리해줘"라고 요청하면 마무리 품질을 높일 수 있습니다.
